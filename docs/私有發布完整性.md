# 私有網站發布完整性

發布以 `scripts/private_web_release.py` 處理已提交的版本。原始工作區的未提交檔案不會進入產物。

`stage --ref <SHA>` 從 `git archive` 取得精確位元組並組建，保留完整專案至下列測試完成：

1. `python -m unittest discover -s tests -b`。
2. `python -W error::ResourceWarning -m unittest wavedeck.tests.test_smoke -b`。
3. `python -m unittest tests.test_dist_scrub -b`。
4. 依檔名排序執行全部 `tests/*selftest.js`。

隱私清理測試會改寫 HTML，因此前端測試之前會重新解開同一份 Git 封存並組建。全部測試後再重建一次，確認程式逐檔雜湊與最初受測組建相同，才裁剪 WaveDeck 私有站不出貨的內容。資料種子恢復為 Git 位元組；Python 位元組碼不出貨。選用研究依賴及作業系統條件依原測試規則處理，跨平台與研究 CI 仍是外部發布門檻，不能以單機 stage 代替。

清單的 `contentSha256` 包含每個程式與組建檔案，排除 `data/`、`logs/` 和清單本身；`seedSha256` 獨立記錄公開資料種子。重用 stage 與每次 promote 前均重新驗證。修改、缺檔、多檔、連結或識別不符即拒絕。舊 stage 沒有雜湊時必須重新 stage；不可自行補寫 `tests: passed` 或雜湊假裝已受測。

`promote --release <release-id> --approve` 應由發布包裝流程在確認 CI、完整 SQLite 一致備份、停止己方服務後呼叫。發布器本身不會操作服務、複製執行期 DB 或建立 DB 快照。它在同一安裝根目錄建立候選版本，核對複製內容，保留不受程式清單管理的本機設定，再以有交易紀錄的目錄切換發布。既有 `data/` 與 `logs/` 直接搬移，原檔案保持同一實體；只為缺檔加入經驗證的公開種子。舊版程式留在 `backups/`。

本機設定優先依前版逐檔清單辨識；舊清單只有頂層管理範圍時，使用仍保留的相同 SHA stage 確認檔案範圍。管理目錄存在但兩者皆不存在時停止，必須保留或重新建立相同 SHA 的 stage 才能發布，避免誤刪目錄內的本機設定。設定與新版程式路徑衝突時停止切換，不覆寫設定。

Windows 目錄切換是可回復交易，並非整組單一原子改名。發生例外會依交易紀錄恢復原版與資料；程序中斷後，可在服務停止時執行 `recover --approve`。狀態無法驗證時保留所有目錄與紀錄，交由核對，不猜測刪除。`rollback --approve` 驗證前版程式，再走相同候選切換流程，保留最新資料及本機設定。此為程式回復，不能代替 schema 遷移前的完整 DB 備份。

`/health` 的 `runtimeCommit` 固定為程序啟動時讀到的完整 SHA，避免磁碟已更新但舊程序仍載入舊程式時誤報新版。私有發布清單優先，開發 checkout 才使用自身 Git HEAD；無可靠版本則回傳 `null`。正式驗證必須核對這個欄位、實際服務的靜態檔案與 UI。

`scripts/go.ps1 -UpdateOnly` 可保留指定行情 CSV、SQLite 與備份 JSON 的本機變更；若遠端更新涉及相同資料路徑，在切分支前即停止。非資料變更仍阻擋，更新器不使用 stash、reset 或強制覆寫。
