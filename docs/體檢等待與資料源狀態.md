# 體檢等待與資料源狀態

個股體檢沿用 `/stock-signals` 的資料與計算契約；技術分數仍為獨立的 0–100 分數。這次修正不新增資料來源、權限、模型或對外服務。

## 載入、取消與重試

- 體檢成功與失敗回覆，都必須仍屬於原卡片、股票、市場、圖表路由及體檢分頁，才能更新畫面。切換頁面、換股或重新載入後，舊回覆不覆寫新畫面或新快取。
- 同一卡片正在等待時，單純重繪沿用該次請求；手動重試會取得自己的取消訊號。當前卡片真正失敗或逾時，仍顯示錯誤及「重試體檢」按鈕。
- 體檢的 45 秒前端期限維持不變。`AppKernel.api.getJson/postJson` 的期限涵蓋完整 JSON 讀取；`TimeoutError` 與呼叫端主動取消的 `AbortError` 分開。原始 `request` 回傳的串流仍由呼叫者控制。
- 既有遠端行情補抓最多等待 8 秒，來源工作同時最多 4 個。工作繁忙或逾時會保留本機日線，透過 `dataWarning` 明示原因，資料不足仍拒絕產生完整體檢。逾時後才到達的遠端結果不寫入資料庫。
- 補抓期限不等於整個 HTTP 請求的保證上限：本機資料讀取與計算仍需時間。來源工作可能在底層網路呼叫結束前繼續占用固定工作名額；介面不再等待該晚到結果。繁忙不被記為來源失聯，`allow_network=False` 仍不提交任何來源工作。

## 設定頁的系統資料源

`/datasources` 的 `status` 主要是物件，不能直接串接成文字。設定頁分別呈現既有的紀錄數、發布檢查、過期序列數、提供者與檔案修改時間，並相容舊版字串狀態。來源欄位皆跳脫 HTML。

數值 `0` 與未提供分開；`live/daily` 介面既有的 `{updated:0,count:0}` 是能力占位值，顯示「尚未提供快取統計」。來源類型「官方」不是新鮮度判定，檔案修改時間也不是行情資料日；清單不宣稱資料為最新。載入失敗、格式無法識別與成功取得空清單分別顯示，不把錯誤當成沒有來源。

舊版來源註冊表可能在缺檔或解析失敗時也回報零，因此欄位標為「來源回報紀錄數」，不能據此證明快取成功讀取。檔案時間未提供時另標示存在與可讀狀態待核對；前端不捏造後端尚未提供的失敗原因。

## 重現與驗證範圍

離線測試固定交錯順序，覆蓋舊回覆成功／失敗、換股與市場、分頁／路由、卡片替換、真正逾時、重試、JSON 本體停止傳輸、有界來源繁忙、晚到結果不寫入及禁止連外。瀏覽器測試涵蓋來源物件、缺值／零值、錯誤文字、安全跳脫與較舊設定請求。

曾觀測到密集巡覽後的體檢被瀏覽器取消，私有閘道稍後記錄下游斷線。隔離測試證明了可導致此類等待與覆寫的程式路徑；單筆閘道耗時不能證明當時全部時間都花在同一遠端來源。發布後須以「先密集巡覽、再重新載入個股體檢」順序復測，並保留原始失敗證據。
