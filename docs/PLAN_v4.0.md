# Stock Terminal v4.0 — 突破與架構性增幅提案

> v3.9 已把「功能廣度」做滿（看盤／型態／選股／回測／策略／警報／籌碼／基本面／AI 報告）。
> v4.0 的主題不該是「再加更多按鈕」，而是 **三件能讓整個系統升級一個層次的底層投資**：
> ① 一個本機資料骨幹、② 一位本機 AI 副駕、③ 投組層級的專業分析。
> 這三者互相加成，且剛好吃滿你的硬體（96GB RAM + RTX 5080）與你的市場派研究風格。

---

## 一、架構骨幹：本機時序資料庫（最關鍵的一步）

**現況痛點**：每個功能各自即時打 Yahoo（LRU 快取在記憶體）。回測要重抓、離線不能用、跨功能無法共用同一份乾淨資料、歷史深度受限。

**做法**：導入本機 **SQLite/DuckDB** 當單一資料源——
- 一張 `bars` 表（時間序列 K 線）、`fundamentals`、`chips`、`etf_holdings`、`news`。
- 抓取層統一寫進 DB；前端／回測／選股／警報全部讀 DB（Yahoo 只在缺資料時補抓）。
- DuckDB 對「全市場 1800 檔 × 數年日線」做欄式分析快到離譜，**全市場回測／選股從分鐘級變秒級**。

**為什麼是架構性增幅**：之後每個新功能都站在「快、乾淨、離線、可重現」的資料層上。這是把工具從「即時查價」升級成「可做研究」的分水嶺。96GB RAM 讓整個資料集常駐記憶體。

---

## 二、突破級功能：本機 AI 副駕（吃滿 RTX 5080）

**現況**：AI 報告靠 Claude API（要金鑰、要連網、單次八章節）。

**v4.0 願景**：在你本機跑一顆量化過的開源 LLM（RTX 5080 16GB 可跑 7B~14B 級），搭配 **RAG（檢索增強）**，做成常駐副駕：
- **自然語言問你的盤**：「我的持倉裡誰對台積電 capex 砍單最敏感？」「這週台股量能結構偏多還偏空？」——它讀你的 DB（持倉／籌碼／量能）+ 新聞向量庫即時回答。
- **主動洞察**：盯著 watchlist + 市場資料，盤後自動產出「今日對你重要的 3 件事」，離線、零 API 成本。
- **RAG 知識庫**：把財報、法說、新聞做向量索引（本機向量庫），讓 AI 的判斷有出處、可追溯，而非空想。
- Claude API 仍保留當「深度模式」，本機模型當「即時、免費、隱私」模式，兩者並存。

**為什麼是突破**：把「按一下產一份報告」升級成「一個一直在幫你看盤、懂你部位、講得出理由的分析師」。完全本機 = 隱私 + 零成本 + 隨時可用，正好對應你「資料零雲端」的設計哲學與你重深度研判的風格。

---

## 三、專業深度：從「個股」升級到「投組與市場結構」

你是市場派、重結構，但目前分析多半停在單一個股。v4.0 補上投組與大盤結構層：

- **投組風險儀表板**：相關性矩陣、Beta、波動／VaR、最大回撤、產業／供應鏈曝險分佈。一眼看出「我整包部位其實 70% 壓在台灣 AI 供應鏈同一條船上」。
- **供應鏈曝險圖**（呼應你的核心論點）：把持倉/自選對應到「晶圓→封裝→CPO→伺服器→散熱」節點，量化你在每一段的曝險與連動，TSMC/費半變動時直接看衝擊傳導。
- **市場內部結構**：漲跌家數、新高新低、產業輪動熱力、量能結構（你關注的 8000億→1.2兆）做成每日內部結構面板，回答「這是健康的多頭還是少數權值撐盤」。
- **基本面深化**：三大財報、簡易 DCF/成長性估值、營收動能 YoY 熱力（你已重視月營收）。

---

## 四、更好用：專業工作流

- **Workspace 佈局保存**：多套版面/圖表組合一鍵切換（像 TradingView 的 layout），盤前盤後不同配置。
- **遠端/手機安全存取**：本機 server + Tailscale，通勤時手機也能看自己的終端機（純自用、加密、不公開）。
- **統一警報中心**：警報歷史、已觸發紀錄、複合條件可視化編輯、手機推播匯流。
- **即時推送**：用 **WebSocket** 取代現在的輪詢（30s/45s），LIVE 真即時、伺服器負擔更低。

---

## 五、工程品質（讓它「專業」而非「能跑」）

- **測試骨架**：前端模組（解析/指標/型態）+ 後端端點的自動化測試；接 CI，改動即跑。
- **模組契約延伸**：把 v3.9 的 `Toolbar` 註冊表擴成「功能模組宣告」（id/分類/相依/設定 schema），未來新指標/策略可用宣告式掛載，甚至開放你自寫外掛。
- **錯誤監測**：本機錯誤紀錄面板（已有 datahealth 資料源健檢，可延伸成全系統健康頁）。

---

## 建議落地順序（一次一塊、各自可獨立交付）

| 階段 | 內容 | 解鎖什麼 |
|---|---|---|
| **4.0-A 骨幹** | 本機時序 DB（SQLite/DuckDB）+ 抓取層改寫 | 全市場秒級回測/選股、離線、資料可重現 |
| **4.0-B 投組層** | 投組風險 + 供應鏈曝險圖 + 市場內部結構 | 從個股升級到結構視角（最貼你的市場派） |
| **4.0-C AI 副駕** | 本機 LLM + RAG 新聞/財報向量庫 + 自然語言問盤 | 突破級體驗、零成本即時分析 |
| **4.0-D 工作流** | WebSocket 即時、Workspace、遠端、統一警報中心 | 專業日常使用體驗 |
| **4.0-E 品質** | 測試/CI + 模組契約 + 健康頁 | 可長期維護、可擴充 |

**我的建議**：先做 **4.0-A 資料骨幹**（其他三塊都站在它上面），接著挑 **4.0-B（最貼你的研究風格）** 或 **4.0-C（最有 wow、最吃你的硬體）** 其一當 v4.0 的旗艦。
