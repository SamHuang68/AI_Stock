# 突破組合工程研究契約

版本：`breakout-capital-vidya-engineering-v1`。

既有 K 線事件研究文件把 VIDYA、出場口徑、資金限制與同日多股競爭列為後續條件。這份能力補上明確的工程研究，不宣稱重現文章作者未揭露的公式。第三階段官方參考價比較契約、原始價格、事件語意與影子帳本不改寫。

## 固定研究假設

研究只接受目前已建立的 2330、0050，依三項既有首次突破事件各自運行獨立現金帳戶。不得把三個獨立結果相加當作一個組合。讀取器固定近五年，另取最多 253 個市場交易日暖機；歷史缺口保留，暖機不足保持不可判定，不用較短窗口代替。所用資料為現在核對後的歷史版本，不是當時可取得資料的完整重建。

指標採工程版固定窗口 CMO-VIDYA：

1. 每個觀察日使用截至當日的最近 60 棒；每個觀察日重新初始化，避免研究期間尾端或未來公司行動改變早期基準。
2. 使用當日為基準的官方參考價比較收盤。只乘入已生效且已核對因子，不調成交量、不改原始成交價格。
3. 前 20 棒收盤平均作初值。其後每棒計算最近 9 次收盤變動，`U` 為正變動和，`D` 為負變動絕對值和；`absCMO = abs(U-D)/(U+D)`，分母零時為零。
4. `alpha = 2/(20+1) × absCMO`，`VIDYA(t) = VIDYA(t−1) + alpha × [close(t)−VIDYA(t−1)]`。平滑長度、CMO 長度與暖機窗可由純函式 config 明確設定；預設固定如上，CMO 長度不得大於平滑長度。

這是有界窗口與均線初值的工程選擇，不聲稱為文章或其他軟體的隱含 VIDYA 定義。公司行動資料不足、來源或原始價格基準未知、窗口缺值時不計算指標。

收盤確認首次事件，下一個市場交易日開盤假設買進。收盤低於當日 VIDYA，或低於／等於原始進場價的 92%，下一個市場交易日開盤假設退出。8% 為工程參數；停損比較原始進場價格，交易成本另計。開盤跳空按實際原始開盤計算，不保證在停損門檻成交。

## 資金與成交

預設初始本金 1,000,000，最多同時持有兩檔；每檔投入上限預設為初始本金的 50%，受可用現金限制。`capitalBasis` 可明確選擇 `initial`（初始本金）或 `previous_close_equity`（前一日已知收盤權益）的比例配置；後者讓已經發生的盈虧影響下一次股數，但不看進場日收盤，前日權益未知時拒絕新配置。唯讀入口另附 `equitySizing` 獨立複利比較，沿同份資料快照與規則，不混合兩種口徑。最小交易單位預設一股並取整；不借貸、不加碼、不自動再平衡。設定可增加整數交易單位，但沒有假裝已模擬整張／零股撮合差異。

同一天先處理既有待退出部位，再依股票代碼遞增處理前一天確定的待進場。現金不足或已達持股上限的候選保留拒絕原因。無成交、品質缺漏、一價棒不能證實開盤成交時，該次進場取消，不順延；退出受阻則保留原部位並於後續實際交易日繼續嘗試。

分別計算未計成本、買賣各 0.25%、買賣各 0.50% 三種情境。現金扣付及收入按實際股數、原始開盤與成本計算，這些是研究摩擦情境，不宣稱為正式市場稅費。每棒收盤按原始價格估值，列出現金、權益、曝險及持股數；期末未平倉不強制成交。

公司行動期間沒有股數轉換、除息現金或其他權利模型，因此持有期跨事件後保持收益未知，並停止新增部位。不能預先看到未來事件而避免原本會進場的交易。未知估值或訊號／指標判定使整體報酬、最大回撤不具備完整依據；可核對逐筆、曲線及問題明細仍保留，不把缺資料當作零回報。收盤後才發生的重大斷點不會追溯取消當天早已排定且可核對的開盤出場。

0050 基準使用研究首日起點之後的下一個市場交易日開盤、相同初始本金與成本情境，持有至期末按市價估值。它與策略曝險、持有期不同，只是市場參照。基準跨公司行動或資料未知同樣保持未知；唯有雙方完整才顯示超額百分點，缺失不補零。

## 純函式與讀端

```python
build_portfolio(datasets, market_dates, *, sample_start=0, as_of=None, config=None)
build_saved_portfolio(db_path, as_of=None, *, now=None)
```

`datasets` 必須含 `2330`、`0050`，各項含 `rows`、`calendar_years`、`action_days`、`action_coverage`、`adjustments`。rows 沿官方正規化格式，含原始 OHLCV、來源、issues 與 `priceBasis='unadjusted'`。市場日期時間軸不可重複、不可跳過預期交易日；缺 row 由純函式保留成缺口。輸入不被修改。

唯讀入口使用既有 `K線事件` 的 `_read_bars`、`_normalize_bars`、`_read_adjustments`、`freshness`、`range_start`。兩檔、日曆、公司行動與調整證據均在同一個 SQLite `mode=ro`／`BEGIN` 快照讀取。沒有補資料、建表、網路或寫入影子帳本的路徑；不存在的資料庫回傳 unavailable。

回傳欄位：

- `version`、`config`、`inputDigest`、`range`：版本、所有工程參數、重現摘要、實際市場日與暖機數。
- `assets[]`：每日收盤、VIDYA、價格基準日、品質原因、各規則 eligible 與首次訊號；並附官方調整證據。
- `rules[]`：三個既有規則，各自包含 `scenarios.gross/baseNet/stressNet`。
- `benchmark.scenarios`：相同成本情境的 0050 市場參照。
- 各情境：`status`、現金／權益曲線、逐筆已完成交易、`openPositions`、`pending`、`rejected`、`decisionIssues`、有效資產日數、報酬及回撤。`unknown`／`insufficient` 不是零績效。

目前能力沒有量價容量、委託簿、盤中停損、市場衝擊、群聚顯著性、多重嘗試校正或樣本外／前瞻驗證。因此完成工程模擬不等於完成策略有效性驗證。

## 驗收證據

`tests/test_突破組合研究.py` 的 18 項隔離案例涵蓋手算 VIDYA、同日現金競爭、取整、隔日開盤、成本與跳空、VIDYA 退出、停損、複利盈虧再配置、前日未知權益拒絕新部位、無成交、期末未平倉、未來資料隔離、公司行動未知、基準公平邊界及原始輸入不變。SQLite WAL 測試在讀 0050 後由另一連線更改 2330，證明本次報告保留原快照、下一次才看到新價格；還原測試 writer 後整庫 iterdump 一致，證明讀端沒有其他寫入。

所有案例使用合成資料及暫存 SQLite，封鎖網路，不操作正式 DB 或程序。不以合成案例報酬主張真實市場績效。
