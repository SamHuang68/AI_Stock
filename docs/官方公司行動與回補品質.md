# 官方公司行動與回補品質

一般上市個股官方回補與背景日線更新共用四類公司行動：除權息、減資、面額變更、ETF 分割。四路來源全部取得且解析成功，才在同一資料庫交易內提交涵蓋；失敗或取消不會留下半套事件或假涵蓋。所有取得均沿用既有官方網址與請求預算。

`corporate_actions` 與 `action_price_evidence` 保留首次事件。`action_source_receipts` 附加保存請求網址、期間、實際取得時間、原始回應雜湊、解析版本及完整解碼回應；`action_price_revisions` 保存後來的數值差異或來源撤回。解碼回應不宣稱可取代原始 HTTP 位元組。相同事件重抓不更動首次證據；來源修訂未核對前，比較頁會拒絕使用相關因子，不自動選用新值或清除爭議。

涵蓋由四類收據的共同連續期間決定。不同期間之間有缺口時，不以最早／最晚日期包成完整涵蓋。舊三類紀錄保持可追溯，但不能直接升級成四類已核對。純除息和 ETF 分割的官方參考價仍只用於歷史價格比較，不代表已取得精確配股權利或含息投資報酬。

官方日線回補的 `ok` 表示工作流程完成；`qualityComplete` 才表示本次預期交易日均具完整收據、價格與成交量皆核對通過。`quality` 分別列出預期、已有觀測、接受、衝突、缺日、無效及缺收據的筆數與日期。同一日可以同時屬於「已觀測」及「衝突」，各分類不能任意加總。

只有選定月份的預期交易日全具有效收據才重用快取。已取得有效收據但有量價衝突時，重用來源並列出衝突；缺收據或收據損壞時，在使用者所選標的、1／3／5 年及既有請求預算內重新取得。`reusedMonths`、`fetchedMonths` 列出實際處理月份；限額或取消仍是未完成工作，已完成月份保留供續補。

`STOCK_DAY` 的原始 UTF-8 回應與真實取得時間透過相容的二項解包回傳附帶保存。只有重播已存在的解析值、沒有原始收據時，仍可保留觀測，但不能假造原始回應或宣稱完整核對。官方修訂不覆寫首次行情，也不更新全市場完成收據來冒充個股以外的涵蓋。

這些檢查驗證資料契約，不代表策略有效。前瞻結果仍需等待真實交易日成熟。

全市場 `MI_INDEX`／`dailyQuotes` 匯入目前只保存解析後日線、來源摘要與完成日期，尚未保存本輪個股 `STOCK_DAY` 等級的完整 HTTP 原始收據。更新摘要的 `sourceReceiptScope` 明示此限制；全市場工作完成不代表逐筆完整收據核對，本流程也不額外逐檔下載個股來源。

Yahoo 的 `queryCoverage` 記錄成功請求的期間，不保證每天都有行情。只有既有查詢起點涵蓋本次起點，才從既有結束日前七天重疊續補；起點不足時仍請求完整選定期間，不用兩個孤立行情日期冒充來源涵蓋。
