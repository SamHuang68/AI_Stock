# PDF 匯入升級

PDF 匯入由 CDN 上的 3.11.174 升級為同源固定版本 6.3.289，使用官方 legacy ES 模組。主模組、worker、CMap、標準字型與 Wasm 共同固定版本；首次匯入才載入。保留純文字擷取流程，不啟用文件指令碼，PDF 內容在瀏覽器處理。

官方 npm 套件下載後先驗證 SHA-512，再擷取所需 201 個原始檔案，共 5,356,630 位元組。`assets/vendor/pdfjs/6.3.289/來源資訊.json` 保留來源、完整性值與逐檔 SHA-256；`.gitattributes` 防止換行轉換破壞原始資產，相關授權隨檔保留。

6.x 已移除 `PDFDocumentProxy.destroy`，改由 loading task 在成功、錯誤與 120 秒解析逾時後清理資源。清理最多額外等待 5 秒，之後明確終止自行持有的公共 `PDFWorker`，避免結束握手卡住或清理失敗遮蔽原始錯誤；每頁讀取完成亦清理資源。新版不再接受 `isEvalSupported`，因此不保留失效參數。密碼與損毀文件顯示可處理的錯誤；解析失敗發生在寫入計畫之前。實檔測試同時找出四位數價格被誤判為股票代碼的既有缺陷，現排除買區、突破、站穩等價位前綴，包含尾端冒號、括號單位與價位後綴。

伺服器明確提供 `.mjs` 的 JavaScript MIME 與 `.wasm` 的 WebAssembly MIME；私人網站沿既有靜態資產路由轉送。發布與分享包的必要檔案檢查包含新版主模組、worker 及來源資訊。分享包隱私掃描新增 `.mjs`／`.cjs`；官方 worker 的內嵌編碼資料誤中郵件規則，例外僅限精確路徑與固定官方 SHA-256，其餘規則照常執行，修改後的檔案不可自行取得例外。

## 可重現驗證

- `node tests/PDF匯入隔離_selftest.js`：版本比對、並行載入、載入失敗重試、文字排序、錯誤與逾時清理。
- `node tests/PDF實檔相容性_selftest.js`：實際新版解析器讀取中文兩頁、一般兩頁、空白、密碼保護與損毀文件，確認計畫欄位及七個 loading task 均結束。
- `python -m unittest tests.test_pdf_assets -v`：201 個檔案雜湊、中文 CNS 字型編碼、真正 HTTP 伺服器及私人閘道的資產位元組與 MIME。分享包不含私人閘道時，只略過該 HTTP 測試。
- 經本機 HTTP 開啟 `tests/PDF匯入瀏覽器驗證.html`，按「執行完整驗證」：實際瀏覽器 module worker、中文 CMap、失敗後恢復及 worker 終止。測試計畫僅保存在頁面記憶體。

文件均由專案自行產生，無使用者交易或個人資料。中文範例明確設定 `UniCNS-UCS2-H` 搭配 CNS1 字型，避免測試產生器的錯配編碼造成假性回歸。

目前不包含 OCR；僅有影像的掃描 PDF 不會產生可解析文字。不同表格排版仍受既有文字排序與欄位規則限制。legacy 版本仍需現代瀏覽器；桌面 Chromium 與 Node 驗證不代表已測試 iPhone Safari。完整 CI 與兩側部署驗證以精確提交的交付紀錄為準。
