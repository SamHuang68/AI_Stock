# 個股健診休市與歷史資料分析修復

## 問題與根因

2026-09-20 週日，實際頁面查詢 2330 顯示「暫時無法健診」，但 `/twquote` 已成功回傳 2026-09-18 的有效成交價、前收參考價與來源日期。健診把 `stale=true` 一律當作不可分析；原 `/quote/2330.TW` 備援又回到相同報價處理器，並未讀取歷史資料。

## 修正後行為

- 有日期、有效價格與前收參考價的最近成交可以分析；休市、非一般交易時段與歷史來源皆明示分析前提，不宣稱即時行情。共用即時行情防線維持原契約。
- 盤中被報價防線保留為 `lastKnownPrice` 的舊成交，只能以來源日期做歷史回顧。
- 主來源錯誤或資料不足時，同時讀取既有本機日線與 Yahoo 日線備援，選擇資料日較新的有效來源；同日優先本機。既有市場尾碼解析支援上市與上櫃。
- 日線以兩筆有效價格與實際起迄日期計算，明示未調整除權息。Yahoo 多日 `chartPreviousClose` 不作最新一日的前收價；當日日線說明可能尚未收盤。
- 個股與指數必須具有相同資料日期；日線區間還需相同起日。缺乏對齊基準時仍分析個股，並說明不能判定相對強弱。
- 拒絕未來日期、矛盾來源日期、可疑資料、非正數價格及計算溢位。
- 主查詢最多等待 8 秒；歷史備援並行再等待最多 8 秒。連續查詢、關閉與離頁會取消舊工作，晚到結果不可覆蓋目前結果。
- 健診結果與尚未送出的代號會保留至市場總覽的定時重繪後。長分析前提可在桌機與手機上完整閱讀。

## 驗證

`tests/個股健診歷史分析_selftest.js` 使用完整正式 Pulse 模組與真實建置、渲染、表單處理，只替換 DOM、網路及時鐘。測試已列入發行套件與 Private Web 的必要檔案及回歸流程。

工作目錄 `scratch` 保存修復前的持久化追蹤、舊版紅燈證據、行為測試、來源邊界覆核及發布資料保留紀錄。最終版本、CI 與雙端真實操作結果由完成紀錄記載。
