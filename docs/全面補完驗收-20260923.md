# 歷史階段補齊與研究工作流驗收

本輪承接 2026-09-08 全面升級計畫的 S1–S6，以及 9/22 文章研究第三階段後的工程缺口。舊全面升級 S2 與文章研究第二階段是不同工作；本輪逐項承接行為，沒有直接合入未發布的舊提交覆蓋後續修復。

| 文章後續工程研究 | 2330／0050 三規則、CMO-VIDYA、停損、資金上限、候選競爭、初始本金及前日權益複利配置 | 同一 SQLite 快照、輸入品質摘要、前日權益未知拒絕配置、成本與基準 |

| 第三階段首筆影子觀察 | 透過真正每日匯入成功 hook 建立首次紀錄，保留實際取得時點；同日重跑不覆寫 | 正式兩端各 4 筆；2 檔 × 原始／參考價比較，輸入摘要一致 |

- 非作者覆核修正四項研究正確性問題：來源品質入庫遺失、統計誤用目前全域協定、未來收盤改寫已排定開盤成交，以及組合輸入摘要漏記資格資料。
- 最後契約核對補上全部 14 個公開決策欄位差異、實際模型目的地綁定、獨立伺服器請求收據、頁面離開時同步復原暫存，以及更新中心的私人研究狀態。沒有實際呼叫模型。
- 發布封存使用精確 Git 提交。瀏覽器截圖與 JSON 收據保存在安裝根目錄下的獨立驗收目錄，不納入正式程式內容。

- 正式每日補齊前，兩端四類資料庫各建立 SQLite 備份，共 8 份，全部通過完整性檢查。兩端每日匯入日期推進至 9/22，首次影子取得時點是實際的 9/23 01:22（臺北），沒有回填成 9/22 當時已觀察。

## 完成範圍的界線

工程可驗證的是計算、儲存、時序、權限、操作及發布行為。下列項目需要另外的證據，不能因程式完成而改稱已完成：

- 尚未發生的前瞻成果，以及足夠樣本的有效性與統計推論。既有已看過的五年歷史不能重新命名為真正未見資料的樣本外。
- 文章作者沒有揭露的箱型／VIDYA 細節。本輪明示工程公式，沒有聲稱完整還原原策略。
- 公司行動期間的實際持有權利、完整含息報酬及委託容量。來源不足時保留未知，不以參考價比值冒充股數轉換。
- 實體 iOS／Android、真實模型輸出品質與帳戶費用。本輪手機尺寸使用真實 Chromium 模擬，模型以受控串流驗證，未啟用新付費服務。

這些界線不是遺漏的實作階段。未來新增資料、實體裝置或模型驗收時，應另記條件與結果；不能覆寫首次研究紀錄美化成果。
