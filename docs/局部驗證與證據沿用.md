# 局部驗證與證據沿用

2026-10-11 起，日常 CI 與發布 stage 使用明列的 `.github/驗證計畫.json`；不再以新提交或新發布為理由自動執行 ST／WD 全套。這是 Sam 本次明確批准的驗證流程修訂。

通用核心位於 `tools/codex/`，可安裝至 `C:/Users/Sam/AI-Workspace/tools/codex/` 供所有專案使用。`scripts/變更驗證.py` 只是本專案的薄入口。全域入口與 CI 使用相同原則，但不宣稱能理解任意測試程式的隱含呼叫。

## 計畫契約

計畫明列穩定的 `project`、完整 `baseCommit`、`scope=targeted` 與每個案例的 `id`、`reason`、`changes`、`inputs`、`kind`、`targets`、`timeoutSeconds`。受影響檔案及真正的測試檔都必須納入 inputs，不接受萬用字元。Git 變更未被案例或明列文件涵蓋時直接失敗；無關案例同樣拒絕。PR／main 事件基底須與計畫一致。

支援 unittest 明列模組／方法、單一 Node 測試檔，以及明列 Python 檔案的 AST 語法解析。輸入應涵蓋測試實際使用的程式、fixture、設定及鎖檔；主控需沿用開發前資源查核，不能省略相依來製造命中。環境準備 `prepare` 可明列 `node`、`browser`、`research`，未列入的瀏覽器與研究環境不安裝。

## 證據與發布

每個案例按專案、測試內容、輸入 SHA256、驗證核心、Python／Node、作業系統及指定環境變數產生指紋。成功證據可跨提交、工作樹與 PR／main 沿用；不同環境不互相代替。即時部署觀測不使用這個靜態案例快取。

CI 只下載同倉庫已完成 `ci.yml` 的指定平臺證據，拒絕外部 fork 來源；只匯入其中通過的案例，其他案例失敗不作廢這份有效證據。下載後仍逐項核對指紋與完整結構。不存在可用證據時執行指定案例，絕不 fallback discovery。失敗、損壞、進行中或逾時的證據會阻擋原樣重跑。

stage 從完整 Git SHA 封存取得計畫及驗證器，完成建置、局部驗證後，以相同封存重建並核對內容。新版 manifest 綁定局部驗證收據與逐檔雜湊；promote 拒絕缺失、篡改、失敗或版本不符的收據。舊版同 SHA 的完整成功 stage 保留相容性。略過測試的 stage 仍不能 promote。

原完整 CI 保存在 `.github/workflows/完整驗證.yml`，僅接受手動 `workflow_dispatch`，需填明確授權原文、來源及完整驗證必要性；push、PR、merge 不會觸發它。必要安全及部署檢查、SQLite 備份、資料保留、程序歸屬及 rollback 保持原契約。
