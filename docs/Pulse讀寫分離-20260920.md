# Pulse 讀寫分離

本輪將 Pulse 的市場更新移出 HTTP 讀取。開啟總覽、Decision 背景輪詢與 Reader 重新整理只取得已提交的市場快照；來源抓取、正式決策發布及歷史寫入由明確的更新工作執行。

## 讀取與更新契約

| 入口 | 行為 |
|---|---|
| `GET /pulse`，含舊 `?refresh=1` | 呼叫 `latest_pulse()`；不抓來源、不提交工作、不刷新原觀測時間。依目前時間重新呈現決策效期。 |
| `GET /decision/context` | 沿用已提交決策唯讀視圖。 |
| `POST /pulse/refresh`，本文 `{}` | 工作先持久接受，再回 HTTP 202、`job.jobId` 與 `coalesced`；已有排隊或執行工作時合併。 |
| `GET /pulse/update-status?jobId=…` | 唯讀取得指定工作，未指定時顯示執行中或最近工作；空資料庫不建立檔案或資料表。 |
| 服務啟動、週期 | 在 HTTP 服務既有程序啟動唯一工作者；啟動時提交一次，之後每次工作完成後等待 60 秒再提交週期工作。 |

尚未有已提交快照時，Pulse 回傳 `ok:false`、明確等待訊息及工作狀態，不由 GET 偷啟動更新。既有快照即使來源過期仍可讀取，效期視圖會如實降級；更新工作成功與來源新鮮度分開判斷。動態快照及工作狀態回應禁止瀏覽器快取。

## 建置與持久工作

原 Pulse 建置移至 `_build_pulse_update`，繼續使用既有行情、廣度、類股、總經資料與決策引擎。市場資金流建置抽成 `_build_marketflow_payload`，由原端點及更新工作共用，承接原先前端暖快取的責任。沒有另建行情管線或更換來源。

`server/pulse_updates.py` 在既有 `data/update_jobs.sqlite3` 增加 `pulse_update_jobs_v1`；不修改既有 `jobs` 表。`ST_UPDATE_JOBS_DB` 可指定隔離測試檔案。工作狀態包括 queued、running、succeeded、failed、interrupted；完成結果只存快照識別、修訂及摘要指紋，完整行情仍由決策庫保存。

SQLite 交易與唯一索引保證同一資料庫只有一筆 active 工作，程序鎖限制單一工作者。啟動無法取得工作者時停止啟動，避免默默提供無法更新的服務。正式本機與 Private Web 仍各自管理執行期資料；不宣稱跨主機共用記憶體或分散式寫入。

工作執行前先持久標記 running。成功結果必須包含相同 `updateJobId`、committed 狀態及有效識別／修訂。狀態寫入失敗時只重試原結果，不能重跑已完成的建置；SQLite claim、終態寫入及對帳失敗採最長 5 秒退避，`workerError` 保留診斷。

重啟會接續 queued 工作；running 若可對應已提交快照則補成功，否則記錄中斷並建立新工作。若下一次發布恢復舊意圖，會依決策歷史的 `updateJobId` 對帳原工作，並保留 `recovery` 的原狀態、錯誤與結果。最近 100 筆終態工作保留於工作庫；active 工作不清除，既有決策與預警保留規則不變。

## 時限與畫面

300 秒是開始新正式決策發布的准入期限。發布鎖內以及記錄新意圖前會檢查 guard；超時顯示 overdue。這不代表所有來源 I/O 都已停止，已持久接受的發布意圖仍由既有恢復協定完成。停止等待或停止服務不能被描述為已取消所有底層工作。

Owner／本機手動更新會顯示排隊、執行與失敗狀態，最長等待 90 秒後停止瀏覽器等待；伺服器工作仍可完成。離頁取消前端等待，不取消後端工作。更新失敗保留前次快照與失敗原因；終態會重新讀取已提交快照。

Reader 只讀 Pulse 及正式決策，不提交市場更新或傳送本機持倉。Owner 既有的背景持倉／風險個人化 POST 保留：它是 ephemeral 純計算，不發布正式市場快照。研究缺值、期權面板展開不再隱含提交刷新，Owner 的明確更新入口保留。

## 驗證

本機完整 Python 回歸 658 項：654 通過、4 項依既有條件略過；36 組 JavaScript 自測通過。新增真實 HTTP、SQLite、程序鎖、故障注入、重啟對帳及前端受控網路測試，另有獨立故障覆驗與六個 loopback gateway 權限案例。

隔離瀏覽器以正式 UI、HTTP 及持久工作佇列搭配固定行情驗證排隊、成功、失敗與快照保留。390px 手機視窗的資訊列寬度 366px，整頁沒有水平溢出。正式分支、CI、雙端版本、來源狀態及資料保留證據另存本次交付驗證紀錄。

執行期診斷位於 `logs/pulse_updates.jsonl`，以 `jobId` 串接 queued、running、terminal、故障退避及恢復事件；原 `decision_context` 發布軌跡與 SQLite 已提交快照可交叉核對。本輪沒有啟用外部訊號通知、付費 AI 或交易介接。
