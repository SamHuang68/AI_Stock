# 結構化研究任務

研究工作台提供「解釋變化、反方檢查、標的整理、歷史回顧」四種任務。先凍結資料並列出規則式證據整理；模型只是使用者明確選擇的研究輔助，不會自動啟動或改變交易、模型設定及正式市場摘要。

## 資料與時點

- 資料包保留目前、比較或當時／事後的完整公開快照、全部證據及所選個股研究摘要，不截取前幾筆。這裡的「完整」指工作台已讀取的公開資料；個股摘要不是完整原始日線副本。
- 私人筆記、假說、持倉、風險設定、紀錄標題及事後筆記不加入模型資料包。歷史回顧先核對整份原研究紀錄的摘要碼，再只抽出公開快照及公開個股研究。
- 快照必須已提交並具有識別與摘要碼。資料包有 SHA-256 摘要；一旦凍結，後續工作台變更不會改寫該包。
- 新模型任務使用目前快照的 `validUntil`／`expiresAt`。未提供效期時，以 `asOf` 的 24 小時為保守上限；缺時點、未來時點或明示來源效期不足都停止新分析。
- 歷史回顧可使用過期資料，但需要當時與事後兩份快照，事後日期必須晚於當時。每項引用帶有 `then`／`after`，不能把事後資料列為當時已知。

## 使用流程與資料邊界

1. 按「凍結資料與整理證據」，完全在瀏覽器建立資料包、逐項證據及前後差異。可複製或下載全部內容。
2. 如需模型，選擇既有快速／深度通道，再按「讀取路由與模型資訊」。這一步只查同源 `/ai/local/status`；已核對為本機 loopback 的快速通道可以探測本機模型列表，外部目的地則延後探測，畫面明示尚未確認可用性。不傳送研究內容或要求推理。
3. 畫面列出主機標籤、提供者、模型、實際模型目的地（不含帳密、查詢參數及片段）、目的地設定摘要、資料邊界、通道及費用未確認說明。路由資訊有效一分鐘。只有 `destinationVerified === true` 才能凍結本次路由；如 Hermes CLI 的實際提供者端點尚無法明確核對，結構化任務停止，不把主機標籤誤認為模型目的地。
4. 使用者勾選本次同意，再按確認執行。前端使用既有 `STAI.request` 傳送 `expectedRoute`；伺服器在推理前核對六個路由欄位（模式、主機、提供者、模型、資料邊界及 `destinationId`），不一致即停止。回應的 `X-ST-AI-Destination-ID` 亦須與確認路由一致，否則隔離。失敗不改用其他提供者或付費後援。
5. Reader 不可查模型路由或執行模型，但可以離線整理、複製與下載公開證據。

既有通道的限制是 prompt 16,000 字元、context 180,000 字元及 HTTP 請求大小。任務在送出前採更保守的 240,000 UTF-8 位元組門檻；超限會停止並保留完整資料包，不讓底層截短資料。

## 輸出核對

模型須輸出純 JSON，包含 `claims`、`limitations`、`nextChecks`。每一項研究推論提供 `evidenceId`、完整 `quote`、`phase`、`interpretation`、限制與後續查證事項。

核對條件包括：引用存在、完整引文精確相符、時點一致、必要欄位完整，且推論內的數字及數字單位在該項所引證據中存在。未知識別、改寫引文、未支持數字、非 JSON、空回覆、錯誤路由與缺少請求識別都會隔離；隔離原文不會列入研究摘要。伺服器回應標頭的 `serverRequestId` 必須存在且與請求識別相符，瀏覽器自產編號不能替代伺服器收據。串流必須由既有 STAI 收到完成事件，斷流不能當作完成。

「引文核對通過」只表示機械核對通過，不能證明推論、因果、數字語意或投資結論正確。畫面持續標示研究推論；完整原文、限制及待查事項均保留。來源文字視為不可信資料，不能改變任務規則或要求工具執行。所有顯示都以純文字或 HTML 跳脫處理。

## 保存、取消與錯誤

瀏覽器以 `st.research.task.v1.*` 的獨立隨機鍵新增不可覆寫事件，保存凍結包、路由、工作狀態、模型、請求識別、完整結果及引用核對。每項事件另有摘要碼；讀取及匯出會核對摘要。損毀原字串仍保留供備份，不會自動刪除、清理配額或改寫原紀錄。

儲存失敗會顯示錯誤。開始狀態不能保存時不送模型；完成時才遇到儲存失敗，完整原文及核對收據留在畫面供複製。頁面重新開啟不會自動重送執行中工作；只有完成收據才能證明已完成。

「停止接收」會取消瀏覽器接收並留下停止要求，不保證後端立即停止。取消後的晚到文字及結果不能覆蓋後續任務。取消、失敗及斷流的原文都不列入研究摘要。

模型串流另使用每任務獨立的 `st.research.pending.v1.*` 同步復原暫存，與不可覆寫正式事件分開。收到首段原文後保存，後續接收最多每秒更新一次；`pagehide`、停止接收及收到完整回應時立即同步保存，不依賴卸載時完成非同步摘要。此暫存會更新為最新原文，因此明確標示可變、未核對，不能列入研究摘要，也不能證明後端已停止。完成收據保存成功後，暫存仍保留並標示對應 `receiptEventId`，不自動刪除資料。

重新開頁可在工作台歷史及完整匯出查看復原原字串；不會自動續跑。儲存失敗會持續顯示複製提醒，停止瀏覽器接收仍可操作。瀏覽器遭強制終止且未觸發 `pagehide` 時，只能復原最近成功寫入的暫存，無法保證保留尚未落盤的最後一秒；裝置或瀏覽器禁止儲存時也不能宣稱已備份。

## 統一工作中心的本機研究狀態

「更新工作中心」另列本瀏覽器 AI 研究任務：開啟時核對全部不可覆寫事件，成功保存正式事件後更新。只讀取本機儲存，不向伺服器傳送任務內容，不新增模型執行或取消按鈕。關閉中心即移除本機事件與跨頁儲存事件監聽。

中心按工作分組顯示任務、最近狀態、模型、提供者、主機、工作／請求識別及凍結包摘要。每頁最多 20 個工作，可前後翻頁；總事件數、工作數、損毀數及未核對復原暫存數均明列。完整匯出包括所有頁面、全部原事件、損毀原字串及復原暫存，工作台亦保留完整內容。

缺少完整完成收據時，中心一律標示「完成狀態未確認」，不能把瀏覽器沒有接收結果宣稱為後端中斷。完成收據只表示有完整核對流程的結果；引文核對不證明模型推論正確。其他瀏覽器或裝置的私人任務不在此清單範圍；讀取失敗時保留先前顯示並明列其狀態可能過時。

## 驗證

離線測試使用正式完整模組並控制網路替身，沒有實際呼叫本機或外部模型：

- `node tests/研究任務_selftest.js`：完整證據、隱私欄位、不可變凍結、紀錄摘要、引用／數字／時點、敵意來源、Reader、確認、效期、容量、路由、串流失敗、逆序與保存失敗。
- `node tests/研究任務面板_selftest.js`：完整面板及正式 STAI 串流接線、預設不呼叫、逐次同意、`expectedRoute`、HTML 跳脫、完成事件及 Reader。
- `node tests/研究任務_selftest.js` 另覆核同步 `pagehide`、重開不重送、原事件逐位元保留、收據取代標示、配額失敗及停止接收。
- `node tests/更新中心研究任務_selftest.js`：唯讀本機狀態、分頁及完整匯出、原字串保留、未確認狀態、保存通知、關閉釋放及儲存失敗。

DOM 替身驗證不代替原生瀏覽器的版面與鍵盤驗收。真實模型可用性、輸出品質及帳戶費用須在使用者明確同意後另行驗證。
