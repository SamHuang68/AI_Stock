# 台指選擇權結構每日自動更新

基底：6eb2769ce18aec2c086c55ff21a8bb922598187b（時段改版）。原始版本 PR #169 基底 e0b11475f40a980289553d18029b916be3d1e457。產品版本仍為 5.0。

## 原因

選擇權結構只能由畫面按鈕觸發 `/options/txo/refresh`，沒有任何排程呼叫它。2026-10-07 實測 local 快取停在 2026-08-16、正式網站停在 2026-09-09。

## 時段（2026-10-07 修正）

PR #169 原設在收盤後 18:30／19:30／20:30。實測 TAIFEX 官方檔（`DailyMarketReportOpt`、`DailyOptionsDelta`）的 `Last-Modified` 為 2026-10-06 22:36 UTC（台北 2026-10-07 06:36）：**D 日資料在 D+1 約 06:36 才發布**，收盤後同日抓不到當日資料，每天只會抓到前一日資料並因現貨日與資料日不同被品質保護標為失敗。

現行行為：

- `server/options_schedule.py` 在交易日 07:00、07:30、08:00、08:30 檢查，09:00 開盤後停止。此時現貨基準仍是前一交易日收盤，與選擇權資料日一致。
- 快取的 `observed.tradeDate` 已不早於「前一個表定交易日」就不再送出；否則透過統一更新中心 `submit('options', {'force': True})` 排入既有的 `options` 工作。週一對應上週五，不是週日。不新增來源、欄位或第二條抓取管線。
- 預設關閉。需在該 runtime 的 `data/options_daily_schedule.json` 寫入 `{"enabled": true}`（必須是布林 true）才會對外抓取 TAIFEX，比照每日日線的擁有者同意檔。
- 時段收據寫入 `data/options_daily_attempts.json`，先寫收據再排隊；排隊被拒會記為 `rejected`，同一時段不重試，下一時段再試。
- 交易日判斷沿用 `台股交易參考.session`：週末、官方休市與無年度日曆的年份都不送出（無法判斷前一交易日時同樣不送出）。
- 啟動掛在 `server.py` 的 `configure_updates` 之後；啟動失敗只印訊息，不阻擋服務。

## 限制

- 只在服務運行時檢查；電腦關機或 09:00 後才開機，當日不補。
- 發布時間 06:36 是 2026-10-07 的單次觀察，不是 TAIFEX 的保證；若之後發布時間改變，需調整時段。
- 既有 `options` 工作在現貨日期與選擇權資料日不同時仍會標為失敗並不發布市場快照，這是既有品質保護，沒有放寬。
- local 與 web 各讀自己的同意檔，不共用；啟用哪一邊需分別設定。

## 驗證

`tests/test_options_schedule.py` 8 個案例（前一交易日跨週末與日曆未涵蓋、預設關閉與非布林 true、每時段只送一次、舊資料時各時段重試、前一交易日資料已存在即停止、週一需要週五資料、時段外與休市日不動作、排隊失敗留收據）。2026-10-07 實測：local 20:43 啟動後補排的 20:30 時段證明排程與收據機制運作，但當日資料不可得，促成本次時段修正。
