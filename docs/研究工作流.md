# 研究工作流與凍結證據

工作台從已提交的 DecisionContext 選取當時與比較快照，逐項呈現市場狀態、證據及來源時間的變化。使用者可以讀取已保存的標的研究、選定持倉關聯前提、保存主觀假說與推翻條件，再新增事後回顧。每次保存都是新紀錄；原始快照、假說與既有筆記不會被回顧覆寫。

市場觀測、規則解讀、主觀假說及策略績效各自保留來源與前提。技術分數不是勝率，固定測試資料不能列為真實觀測；前向觀測尚未成熟時仍可完成凍結、核對、匯出及工程驗證。

組合研究的每日夏普使用 `dailySharpe`，相對 0050 資訊比率使用 `informationRatio`；兩者分開顯示且不加百分號。無風險年率與年化交易日數只沿 `sharpeEvidence` 已提供的設定呈現；未知原因分別來自 `sharpeEvidence.reason` 與 `benchmarkEvidence.reason`，基準不可用不會連帶把有效的每日夏普清空。

## 介面整合

Shell 建立可垂直捲動的 `#mount-research`。進入時呼叫 `ResearchDesk.activate()`，離開時呼叫 `ResearchDesk.deactivate()`；後者中止瀏覽器讀取、保存草稿並要求停止本機模型接收，不宣稱後端已取消。

依序建置：

1. `src/core/研究工作流.js`：`ResearchWorkflow.Store`、公開標的整合與來源界線。
2. `src/core/研究任務.js`：`ResearchTaskCore`，完整凍結、引文核對、狀態沿革與執行器。
3. `src/ui/研究任務面板.js`：`ResearchTasks.mount(container, getInput)` 與 `stop()`。
4. `src/ui/研究工作台.js`：`ResearchDesk.activate()` 與 `deactivate()`。

面板掛載時需要既有 `STAI`；工作台的 `PortfolioContext`、`SC_CHAINS.TW`、`ValuationResearchUI`、`ShellV5`、`UpdateCenter` 均沿用已存在的能力，沒有時明示尚未載入。工作台讀取 `/kline-events?sym=…&range=1y` 的既有本機日線摘要；失敗時仍保留其他已保存的公開領域資料，字尾 ETF 代號不送入只支援數字的日線入口。

## 唯讀 HTTP

`ResearchWorkflowRoutesMixin` 的四個 handler 由既有伺服器與 gateway 接線。query 禁止未知、重複、空白值、不完整百分比編碼與非十進位整數，不接受更新參數。

工作流、標的研究與預警驗證由 gateway 限擁有者存取；固定市場組合研究允許唯讀使用者。工作台對唯讀使用者只顯示固定市場研究，不讀取私人草稿、筆記或受限端點；後端授權仍由正式 gateway 強制執行。

| GET 路徑 | 允許參數 | 資料來源與限制 |
| --- | --- | --- |
| `/research/workflow` | `current`、`previous`、`before`（正整數）、`limit`（1–100，預設 30） | 同一 SQLite 唯讀交易內讀取 `decision_commits`，沒有檔案或資料表時不建立資料庫。完整歷史以 `nextBefore` 分頁。 |
| `/research/subject` | 必須單一 `symbol` | 擷取主線 `_openapi_ds` 的 `__list__` 整表、既有逐股索引、MOPS、法人、產業分類、新聞及 ETF 保存內容；不呼叫抓取器。 |
| `/research/validation` | 單獨 `replay`（64 位十六進位識別）；或 `offset`（0–10000000）與 `limit`（1–100，預設 30） | 延遲呼叫 `early_warning.observation_page(n, path, offset=…)` 或 `replay_observation(id, path)`，完整分母由共用驗證引擎提供，分頁沿 `nextOffset`。 |
| `/research/portfolio` | 無 | 延遲呼叫 `突破組合研究.build_saved_portfolio(datastore.DB_PATH)`；顯示策略、成本情境、資料範圍與樣本切分，不硬填績效。 |

參數錯誤為 400；指定快照／觀測不存在為 404；重播規則、摘要或結果不符為 409；本機資料庫損毀、不可讀或來源模組錯誤為 503。空快照是可用的 `not_started` 狀態，並提示由更新工作中心建立；不可將損毀資料改成成功空清單。

標的研究的 `status` 區分 `available`、`partial`、`not_started`、`unavailable`，`readIssues` 保留不可讀的檔案名稱及原因。`sourceMetadata` 只保留目前主線已有的 `status/url/rows/fetchedAt`；取得時間不會代填成公告日。各證據日期、未知日期、期別與來源原樣保留，ETF 分類日不當成持股揭露日。

## 儲存與復原

研究筆記逐筆保存於 `st.research.record.v1.*`，含 SHA-256 摘要。匯入先核對全部紀錄，重複同內容略過、相同識別不同內容拒絕；中途寫入失敗只回復本次新增項目，保留舊紀錄。完整備份包含可讀紀錄、損毀原字串與未核對草稿；匯入只還原已核對研究，草稿原字串留在備份供人工復原。

任務每個狀態事件另存於 `st.research.task.v1.*`。`ResearchTaskCore.Store.all()` 匯出全部事件、損毀項目及 `st.research.pending.v1.*` 同步復原原文，沒有頁數截斷或配額淘汰。更新中心沿用 `summarize()`；`st:research-task-saved` 只通知工作與事件識別，不夾帶私人內容。

只有保存成功的完整完成收據可顯示完成；停止接收、頁面卸載、連線中斷、逾時及儲存失敗均不能推論後端已停止。`pagehide` 同步保存最新未核對原文，重新開頁不會自動重送。若瀏覽器禁止或耗盡儲存，畫面提供明確錯誤並保留可複製的原文及未保存收據。

## 模型執行與引文核對

離線凍結不會讀取模型路由或呼叫模型。模型輸入只包含公開快照及公開標的研究，私人筆記、假說、實際持倉與風險設定留在瀏覽器。公開來源文字視為資料，不能變成指令。

執行沿現有 `STAI.request({endpoint,prompt,context,expectedRoute,…})`，端點只有 `/ai/local` 或 `/ai/deep`；`expectedRoute` 為 `{mode,host,provider,model,dataBoundary,destinationId}`。路由必須由同源狀態介面提供已核對目的地、完整模型識別及一分鐘內的核對時間，使用者確認目前資料包與路由後才可送出；沒有實際目的地證據時停止，不切換供應者、不擴大權限或額度。

先保存凍結輸入，再透過既有串流接收；收到完整完成訊號後核對真實伺服器請求識別、實際路由、JSON 結構、證據識別、完整引文、引用時點與數字。公開標的證據逐筆引用；晚於所選快照截止日的來源不得列入當時研究解讀，未知日期與同日未知時刻明列。任何核對失敗都隔離模型文字，原文與原因仍可查看及完整匯出。引文匹配只能證明引用存在，不能證明模型推論正確。

## 驗證與剩餘現實限制

本機 fixture 測試：`tests/test_研究工作流.py`、`tests/test_研究工作流邊界.py`、`tests/test_標的研究.py`、`tests/研究紀錄_selftest.js`、`tests/研究任務_selftest.js`。正式 runtime 的跨層 fixture 為 `tests/研究任務面板_selftest.js`，正式 handler 與 gateway 的接線測試包含於 `SubjectHttpTests`，由整合分支執行。

`tests/研究工作台_browser.cjs` 透過固定資料攔截全部請求，使用正式工作台、任務面板與更新中心程式。涵蓋桌機、手機直橫向、200% 等效寬度、焦點隔離及返回、匯出匯入、競態、唯讀角色及 100 次進出清理；測試外殼為固定容器，不能替代全站部署驗收。`ST_PLAYWRIGHT`、`ST_BROWSER_EXECUTABLE`、`ST_BROWSER_OUTPUT` 可指定既有測試工具、瀏覽器與輸出目錄，不需安裝新供應商或呼叫真實模型。

真正前向成熟觀測、外部來源可用性、模型目的地設定與真實策略效果，仍須以實際後續資料證明；本工程不以通過 fixture 取代這些證據。
