# 估值承接與分批成本研究

此模組把官方觀察、使用者 EPS／倍數假設、分批成本分開。它不下載行情、不建立資料庫、不寫入 DecisionContext、不提交委託。一般範圍為臺灣四位數普通股，官方正本益比上限預設 30，可改 40（有效值大於 0、不超過 200）。3529 力旺與 6643 M31 預設另案估值，固定提供研究入口；可明確取消排除。ETF 與其他市場不套一般公司估值。

## 後端整合

```python
from 估值趨勢 import cached_lookup, get_research, run_screen, validate_settings

lookup = cached_lookup(_openapi_ds)
settings = validate_settings({'peMax': 30, 'excludeIp': True})
detail = get_research('2330', database=database, lookup=lookup,
                      settings=settings, name='台積電', chip_history_path=chip_dir)
screen = run_screen(body, symbols=symbols, database=database, lookup=lookup,
                    settings=settings, names=names, universe_source='既有股票範圍',
                    chip_history_path=chip_dir, calc_ind=calc_ind, tech_match=tech_match)
```

`get_research` 回傳 `{row, researchMeta}`，供 `GET /valuation-research/{code}?peMax=30&excludeIp=1` 使用。路由須將 `excludeIp` 解析為布林值；`peMax` 可交由驗證函式解析。保留 `.TW`／`.TWO` 尾碼進後端才能檢查指定交易所。

`POST /screen3` 啟用研究的本文為：

```json
{"research":{"enabled":true,"peMax":30,"excludeIp":true},"tech":{},"fund":{},"chip":{}}
```

路由在一般選股的下載流程之前分流。`run_screen` 回傳 `results`、`scanned`、`techPass`、`matched`、`calculationVersion`、`researchMeta`、`scope`，最多傳回 80 列。`researchMeta.excluded` 是排除原因計數；`separateSymbols` 固定包含 `{sym,name,valuationModel,excludedFromGeneral}` 的 3529、6643 兩筆，不受當次宇集影響。沒有啟用技術條件時不要求技術指標；全為 false／null 的技術欄位物件視為未啟用。選用技術條件時須注入既有指標及匹配函式；OHLCV 不完整不得呼叫指標函式。

`lookup([dataset], code)` 須回傳原始官方資料列或 `None`。`cached_lookup` 直接接受 `_openapi_ds` 的 `('__list__'+dataset) -> (抓取日期, rows)`；只讀字典，不會呼叫 `_openapi_lookup`。抓取日期不能代替來源日期。若提供自行實作的 lookup，也必須遵守只讀快取契約。

## 結果與排序契約

版本為 `valuation-research-2`。各數值缺值一律是 `null`，零營收年增、零殖利率、零量不改成缺值。

| 路徑 | 意義 |
| --- | --- |
| `row.sym/name` | 股票代號與名稱 |
| `row.close/per/yield/revYoy` | 已保存收盤、正本益比、殖利率、月營收年增 |
| `row.market` | 沿用 `market_contract.quote_contract` 的市場報價契約 |
| `row.research.scopeEligible` | 普通股、交易所、正 PER、來源日與上限全部通過 |
| `scopeReasonCode/scopeReason` | 不通過原因的機器碼與可顯示文字 |
| `dataStatus` | `available` 表示估值範圍與價格結構可用；`partial` 表示不足；`not_applicable` 表示不適用。個別營收、籌碼仍須檢查缺值與 `missing` |
| `priceAsOf/priceSource/priceFresh/priceBasis` | 價格交易日、官方來源、新鮮度、原始價格基準 |
| `valuationDate/valuationSource` | 官方 PER 日期與來源 |
| `expectedSession/asOf` | 官方日曆確認的完整交易日／本次研究截止日 |
| `rangePosition` | **文字分類**：接近上緣、帶量越過、越過但量未確認、區間內、跌破下緣，或 null |
| `rangeTop/rangeBottom` | 當日之前 20 個交易日最高／最低價 |
| `distanceToTopPct` | `(前20日高點－收盤) / 前20日高點 × 100`；已越過時為負值 |
| `drawdown100` | 近100日收盤高點至目前收盤的百分比，通常為負或零 |
| `breakoutVolumeRatio` | 當日成交股數除以前20日平均成交股數；前期均量零則 null |
| `revenuePeriod/revenueDate/revenueSource` | 月營收期別、出表日期、來源，三者分開 |
| `income` | 沿用基本面共用契約，不年化 EPS、不重建未知財報期間 |
| `missing` | 資料不足與研究限制文字陣列 |
| `pitFinancialsAvailable/strategyValidated` | 目前固定 `false` |

伺服器預設依區間分類（上表所列順序）、距上緣絕對距離、代號排列；缺值置後。前端切換排序應只針對已回傳列，保持 null 置後並以原索引或代號穩定排序，不能再抓資料。排序不是報酬預測。

## 資料門檻

使用既有 `market.db` 的 `bars`、`bar_quality`、官方交易日曆；唯讀 SQLite snapshot 不遷移、不建表。每筆須對齊 `TW` 市場、股票、來源交易日、TWSE／TPEX、`原始價格` 與 `股` 單位。來源修訂未核對、交易所混用、日期衝突、未完成交易日均不得變成可用觀察。日線遵守既有保守 18:00 完成截點。市場日曆缺漏或過期時不推算目前交易日。

缺 open／high／low／close 保留缺值；不以 close 補 OHLC。缺 volume 不補 0。零成交量保留 0，且不產生區間突破狀態。20／100 日區間依已保存交易日曆補出缺列邊界，不跨缺日壓縮期間。價格未還原除權息，回撤與區間可能受公司行動影響。

PER 日期須有效、單一、不晚於截止日，且等於最近完整交易日才可進一般研究範圍。月營收與財報沿用 `台股基本面` 的來源／期別契約；來源日期缺漏不以抓取日補值。籌碼沿用 `三合一選股.chip_fields`，連續天數只採明載來源日，觀察下限標記保留。

## 前端與成本公式

先載入 `src/core/估值承接核心.js`，再載入 `src/ui/估值承接研究.js`。開啟介面：`ValuationResearchUI.open(symbol, row, settings)`；`row` 可為 null，資料不足時仍可編輯假設。

EPS 下緣 × 倍數下緣至 EPS 上緣 × 倍數上緣形成假設區間。承接／退出價可另填。每批填正數價格、正整數股數，1000 股一張，其餘顯示零股；整股與零股若分單，應輸入不同批次。每跌 10% 新增價格只是可改的試算間距。

令每批本金為 `價格 × 股數`，每批買費為 `max(本金 × 買費率, 最低費)`，總成本為本金與各批買費合計。退出假設一次賣出全部股數，淨額為 `股數 × 退出價 − max(賣出總額 × 賣費率, 最低費) − 賣出總額 × 稅率`。損益兩平價同時解比例手續費與最低費兩段函式。費率可改；預設只是試算假設。價格與費用未套交易升降單位或券商逐筆進位規則。

手算驗證：90、81、72.9 元各 100 股，本金 24,390 元、無費用均價 81.3 元；85 元全數退出獲利 1,110 元。最低買費每批 20 元時總成本 24,450 元，依預設賣費 0.1425% 與稅 0.3% 試算，85 元退出損益 937.1625 元。100 元 1000 股與90元99股分兩批，買費142.5元與20元，總成本109,072.5元。

純核心 `calculatePosition` 回傳 `status`（`no_trades`、`invalid`、`calculated`、`over_budget`）、`batches`、`shares/lots/oddShares`、成本、均價、兩平價、退出損益與剩餘預算。無交易時成本與損益為 null；預算不足保留負剩餘額與原因，不偷偷刪減股數。

本機儲存沿用 `st.valuation-research.v1` 與逐股 `.draft.` key；舊單一 EPS 假設可載入為相同上下緣。未完整批次能存草稿，跨分頁版本檢查防止覆蓋新假設。伺服器資料缺漏、過期、日期倒退或未通過來源門檻時不寫入市場狀態歷程。假設修訂另立比較基準，不當成市場突破事件。瀏覽器儲存不會同步到伺服器或其他裝置。

## 驗證與實際限制

離線 Python 單元測試：`tests/test_估值趨勢.py`；Node 核心與頁面／儲存測試：`tests/估值承接核心_selftest.js`、`tests/估值研究儲存_selftest.js`。涵蓋獨立手算、EPS 區間、零股、最低費、缺值／NaN、不同市場、ETF、來源日、無交易、預算不足、草稿恢復、頁面缺資料、延遲回應與唯讀資料庫雜湊。

工程完成不代表歷史投資策略已驗證。缺當時可得財報版本、當時假設歷程、可靠歷史價格或成交條件時，不輸出勝率、年化報酬或策略有效性。既有官方快取為空、未保存品質欄位或價格不足時，頁面保留完整缺資料原因；本功能不自行下載補齊。
