# 全站三模式投組契約

投組頁、策略決策中心與每日研究工作台共用 `PortfolioContext`，明確區分實際持倉、觀察池及情境模擬。契約版本為 2；三者均不修改市場共用快照。

| 模式 | 輸入與權重 | 空值與缺漏 |
|---|---|---|
| `actual` 實際持倉 | 原始部位的有效股數乘有效最新價格 | 不借用自選、不以成本冒充現價、不補權重 1；任一缺漏停止整體比例 |
| `observation_pool` 觀察池 | 使用者明確選擇的自選清單，每檔等權 | 空清單保持空；持續標示非實際持倉 |
| `simulation` 情境模擬 | 使用者逐行輸入代號與正權重，例如 `TW:2330 40`、`0050 60` | 空情境不帶入其他模式；無效、重複或溢位權重均保留原文與完整分母，不送出部分投組 |

`setMode()` 只改共用模式。`setSimulation(text)` 保存完整情境原文，不自動切模式；`getSimulation()` 取得原文。模式使用 `st_portfolio_mode_v1`；情境使用獨立的 `st_portfolio_simulation_v1`，內容為 `{contractVersion:1,text,inputVersion}`。輸入格式為每行兩欄，市場前綴可選 `TW:`、`US:`、`JP:`、`HK:`；未明列市場時沿既有標的辨識規則，不猜測其他市場。

`resolve()` 保留 `kind`、`label`、`ready`、`holdings`、`coverage`、`issues`，並提供 `source`、`sourceLabel`、`inputVersion`、本頁 `revision`。情境模式的 `simulationInput` 保存完整原文及版本，供本機研究紀錄還原當時輸入；它不加入投組或決策 HTTP 請求，也不加入模型的公開資料包。

模式及情境變動透過同一個 `portfolioContext` 事件通知所有消費端，同源分頁沿瀏覽器 `storage` 事件同步。事件不攜帶原文或權重。Book 與 Decision 的請求指紋含來源版本；編輯、切換或離頁會使晚到回應失效。Book 中段連續編輯不重設相同的 textarea 值，保留游標位置。研究工作台即時重畫關聯，新紀錄凍結當時模式與原文；舊紀錄不變。

切回實際持倉不會改寫原部位或自選清單。情境儲存失敗時，本頁原文保留並明示不可可靠同步，停止計算；不清除其他瀏覽器資料。Reader 不讀取情境儲存、不顯示私人權重、不送出私人或模擬 POST，也不能修改情境。

目前情境引擎只接受 `TW／TWD` 與可確認台股代號（4–6 位數字及可選英文字尾）。其他市場、`TW:AAPL` 等不相容代號或指數成分會在前端契約及後端明示停止計算，原文及完整分母仍保留，不送部分投組。多市場實際持倉沒有明確匯率契約時不可把原幣市值相加；情境權重是使用者假設，不是已觀測曝險。

## 決策中心研究入口

「AI 解釋與證據核對」先透過唯讀 `/research/workflow` 取得已提交公開快照，再掛載既有 `ResearchTasks` 面板。完整證據不截取前十二筆，私人投組、情境原文與風險設定不作為研究輸入。凍結資料、確定性整理、模型目的地與費用確認、引用驗證及不支持內容隔離均沿既有 S5 契約；開啟面板不探測模型、不呼叫推理。關閉或離頁停止接收，不保證後端立即停止。

## 離線驗收

- `node tests/投組資料契約_selftest.js`：三模式、空與缺漏、原文、儲存、跨頁、Reader、反向回應與中段游標。
- `node tests/投組決策同步_selftest.js`：正式 DecisionData 與 Decision UI 的三模式請求、來源版本、私人欄位隔離及逆序回應。
- `node tests/decision_ai_v5_selftest.js`：正式決策入口接 S5、完整公開證據、模型未確認不呼叫、失敗／逾時／離頁及 Reader。
- `node tests/標的研究整合_selftest.js`、`node tests/研究紀錄_selftest.js`：研究關聯、原文凍結、舊紀錄不變及公開模型包隔離。

真正瀏覽器的跨頁、重新開啟、桌面與手機排版驗收另外記錄；這些離線測試不冒稱實體裝置或實際模型驗證。
