# 個股資料與留存解方

本次將三項研究限制可由工程改善的部分接入既有管線：保留來源修訂、分段回收相容歷史、盤後批次更新，以及價量與籌碼分階段留存。功能用於人工判讀，沒有券商下單或模型呼叫。

## 資料來源與保留原則

每日更新讀取 TWSE 上市日線、TPEx 上櫃日線與三大法人、TWSE T86，以及既有 Yahoo 大盤日線。解析器核對來源自己的交易日、OHLC 關係和成交量；不使用另一個來源的日期代填。上櫃法人取明確的買賣超欄位，零為有效值，買進量不能代替買賣超。

來源更新依股票、市場、當地交易日合併。第一次價格保留在既有行情表；後續數值不同時另外存入 `bar_source_revisions`，並以 `bar_ingest_runs` 保留收據，不直接覆寫歷史。這能防止短區段更新靜默混入回溯修訂，但不代表已經校正以前累積的價格基準，也不代表首次取得的數字必然正確。修訂待有證據時逐筆核對。

法人日檔的三個寫入入口共用跨程序檔案鎖，鎖涵蓋完整讀取、合併與原子寫入。上市、上櫃快照都追加既有投信帳本。原行情、既有事件、來源差異不刪除。

## 部分相容歷史

完整覆蓋的既有結果保持獨立。原先整檔未接納的股票，可以另列與來源收盤基準相容的連續區段，每段至少 70 根暖機。原始序列中的缺漏、來源不相容、大盤缺日、已知停止或終止交易都形成斷點；不跨段計算事件與結果。

畫面分別顯示完整股票覆蓋、部分區段的股票數、區段數與日線數。部分覆蓋不能加到完整股票數，也不能直接晉升成研究候選。當前供應商還原快照仍是回溯重編資料，尚非歷史當時可見的點時還原價格；收盤基準相容也不代表全部 OHLCV 已獲官方逐筆認證。

已核對的 1441、6550 停止交易區間另附官方公告識別；停止期間的供應商填值不當成實際成交日。公告外的個股交易狀態仍可能不完整。

## 價量與籌碼分開留存

收盤後第一次取得完整價量時，先凍結 `daily_inputs` 及價量事件。同日稍後法人資料到齊，使用該次首次價量和同版本引擎，將證據存入 `daily_chip_inputs`，再追加籌碼事件。

每個籌碼訊號需要自己的四個連續交易日欄位到齊。缺值不等於零；尚缺資料按股票、訊號與日期列出。重跑不覆寫第一次價量、不重複事件；隔日取得的籌碼不回填前一日訊號。啟用當天也不補造已經發生的事件。

5／20 日結果從下一交易日收盤起算，只有足夠且連續的基準交易日與個股價格才追加。結果價格首次取得後凍結，仍是未還原、未計費用的觀察；尚未成熟不能用歷史回測代替。

## 每日更新與操作

「圖表 → 體檢 → 專業 → 研究維護與每日留存」提供持續授權核取方塊及儲存按鈕。預設關閉；擁有者明確啟用後，交易日 18:30 更新，19:30、20:30 只重試尚未完成來源。當日來源有缺值或衝突時維持部分完成，已完成來源不重抓。主機必須持續運行。

排程設定、同日已完成來源及三個時段收據均持久保存。先保存時段收據才交付工作佇列，避免程序重啟重送同一時段；若交付失敗，保留該時段收據，由下一時段重試。每日更新完成後追加本機觀察。

請求僅含公開代號、日期與行情參數，不上傳帳本，不呼叫模型或券商 API，無已知資料 API 費用。取消勾選並儲存可停用尚未執行的工作；已開始的當次來源處理可能完成。

所有執行在 `stock_daily_sources.json` 與同名 JSONL 保存工作識別、來源、日期、結果與耗時；畫面可展開實際紀錄。資料供應失敗不清空舊結果。官方年曆目前涵蓋 2026 年，未知年度不自動排程；臨時休市仍由來源日期核對拒絕寫入。

## 仍須守住的研究界線

- 29 檔未完整接納的問題沒有全部解開；現金增資、減資與歷史價格混基準仍需逐案證據及持股現金流假設，不能由倍率反推後當成真實報酬。
- 實際前瞻時間無法靠程式縮短。事件數、成熟結果數與研究候選分別呈現。
- 既有 `no_candidate` 門檻不降低。資料更新與部分區段研究不會自動產生買賣指令或保證訊號有優勢。

## 驗證範圍

離線測試涵蓋首次價格不變、來源修訂去重、晚到籌碼同日補足而不隔日回填、共同缺日不跨段、法人並行合併不遺失、官方來源自身日期與買賣超欄位、缺值來源重試，以及排程預設關閉與時段去重。另保留完整回歸、前端自測、同供應商隔離覆核與正式部署驗收紀錄。
