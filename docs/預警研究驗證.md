# 預警研究驗證

預警驗證是既有 Pulse／DecisionContext 的前向事件研究。它保留每日首次可用的輸入與原始規則輸出，並追蹤指定交易日的市場收盤路徑。它不會產生買賣指令，也不是含成交、費用、滑價或投資組合的交易回測。

## 儲存與升級

- 沿用 `data/market_signals.db` 的 `signal_research_protocols`、`signal_research_observations`、`signal_research_outcomes`，不建立另一個研究資料庫。
- `signal_research_schema` 記錄研究表結構版本 `1`。首次寫入先查核既有欄位，在 SQLite savepoint 內增量註冊；不修改其他功能的 `user_version`，也不改寫既有資料列。結構不符或版本較新時拒絕升級，回報研究帳本不可用。
- 新研究協定為 `warning-observation-study/2026-10-v3`。舊研究協定和成果照原樣保留；新版解析器不補算舊協定。舊事件帳本不能補成未觸發觀測分母。第三版以完整年度日曆修正第二版可能受匯入日期缺漏影響的目標日期，不混用兩版分母。
- 研究寫入與預警發布共用交易。研究失敗會回復本次研究異動並明示 `unavailable`，既有預警狀態與 DecisionContext 的確定性規則不變。
- 查詢與重播使用 `mode=ro`、`query_only` 和一致讀取交易，不建檔、不建表、不升級、不解析新增成果。

## 首次凍結與完整分母

每個規則程式摘要、研究協定、訊號與市場日期只保存第一次觀測。所有訊號都納入，包括未觸發、混合方向、來源不足、資料過時及日曆不完整的樣本。相同日期的後續規則轉移仍由既有預警事件帳本承接，不取代研究的首次快照。

觀測保存 `observationId`、`protocolId`、`originSession`、`observedAt`、`eligible`、`unknownReason`、`alert`、`inputDigest`、目標交易日及凍結重播輸入。輸入包含原始 context、pulse、memory、純規則輸出、發布時訊號、起點價格與日曆來源。缺少可信來源時間、起點日期不符、來源時間在未來，或第一個目標交易日已開始時，不列為合格觀測，也不回填為前向訊號。

正式市場日曆只從同資料夾的 `market.db` 讀取已存在的 `calendar_years`，沿用 `year`、`closed`、`opened`、`refreshed_at` 契約。對有官方年度收據的年份逐日建立時間軸，再套用已核對的休市及週末補交易例外；不以 `market_sessions` 已匯入列或行情有價日期決定應有交易日。因此即使行情只匯入到觀測當天，仍可凍結後續應有交易日；兩份行情共同缺一天時，該日仍留在指定路徑並回報未知。

年度收據不存在、日期矛盾、跨年內容錯誤或取得時間不能核對時，保留未知，不將沒有收據的年份當成單純週一至週五。跨年度的起點至第五個目標日必須每年皆有收據；例如只有 2026 與 2028 年時，不得跨過未核對的 2027 年。測試可注入 `research_calendar`，解析只採最初凍結目標，不以後續日曆或行情重新縮短期間。

## 成熟、未知與等待

此市場預警研究使用凍結日曆中的 **1／3／5 個後續交易日**。個股每日留存帳本的 **5／20 日**回報是另一份資料契約，兩者不可混用。市場觀測價至指定目標收盤路徑的同向最大變動達百分之二，才標為事件命中。

- `immature`：指定目標交易日尚未到臺灣時間 18:00。
- `awaitingResolution`：已到期，但尚未有後續發布將該成果凍結；唯讀查詢不代為寫入。
- `unknown`：不合格起點，或首次到期發布時指定日期的可信收盤缺漏、停牌、重複、時間不符或品質有疑慮。後補資料不改寫這次未知成果。
- `mature`：指定路徑每一天都存在可核對收盤；零報酬是數值 `0`，不等同未知的 `null`。

缺日使用原本指定交易日，不跳到下一筆資料，不壓縮缺日、停牌或共同缺日。查詢時間以前尚未取得的觀測或成果不納入當時彙總，排除筆數另列。資料修訂不改寫已凍結成果。

彙總依協定、訊號與方向分層，包含 `observations`、`eligible`、`ineligible`、`unobservedDates`、重複觀測數和各期間分母。每一期的成熟、未成熟、未知及等待解析數相加，等於該層完整觀測分母；分頁大小不改變彙總。原始每日樣本可能重疊，另列非重疊樣本數。命中、漏報與基準比較各自未達至少二十個相關樣本時，不提供比率。

## 程式介面

`early_warning.observation_page(n=80, path=DB_PATH, signal_id=None, *, offset=0, now=None)` 回傳：

- `ok`、`status`、`cacheOnly`。
- `researchValidation`：完整分母彙總。
- `observations`：不含大型重播輸入的逐筆觀測及已凍結成果。
- `totalObservations`、`returnedObservations`、`offset`、`nextOffset`。

資料庫不存在、尚未建研究表或沒有觀測時，回傳 `ok: true`、`status: not_started`，保留空狀態原因。資料庫損壞或結構無法核對時，回傳 `ok: false`、`status: unavailable`，不宣稱零觀測。`performance()` 的原有事件帳本欄位維持相容，另加 `researchValidation`；原有欄位不代表完整研究分母。

`early_warning.replay_observation(observation_id, path=DB_PATH)` 先核對凍結輸入摘要、協定摘要、引擎與政策版本及實際規則程式摘要，再於首次觀測時間重跑純規則。成功回傳 `ok: true`、`status: matched`、`record` 與 `evaluated`。狀態機歷史保留原始觀測，不臆造重演。失敗狀態如下：

| 狀態 | 意義 | 建議 HTTP 狀態 |
| --- | --- | --- |
| `invalid_request` | 空白觀測識別 | 400 |
| `not_found` | 找不到觀測或尚無研究表 | 404 |
| `version_unavailable` | 現有程式無法證明與歷史規則相同；仍提供原始紀錄 | 409 |
| `digest_mismatch`／`protocol_mismatch`／`mismatch` | 摘要或重播輸出不符 | 409 |
| `unavailable` | 資料庫不存在、損壞或無法讀取 | 503 |

歷史資料若只留版本名稱、沒有可核對的規則程式摘要，會回傳 `version_unavailable`，不把目前程式的輸出冒充歷史重播。

## 真實資料限制與驗證

本研究尚無完整歷史時點股票全集或下市全集，不能外推完整市場漏報率，也不能證明可交易獲利。尚未觀測、尚未成熟及樣本不足都屬資料限制，完整程式仍可提供查詢、追蹤、空狀態與重播核對。

`tests/test_預警研究驗證.py` 使用獨立臨時 fixtures，涵蓋首次凍結、可重播輸出、版本差異、同日不可變、跨日與分頁完整分母、成熟與未知零值、共同缺日、僅有當日行情、年度休市與補交易、缺少年度、日曆矛盾、缺日與重複、未來來源、禁止回填、成果不可覆寫、SQLite 唯讀及舊資料升級完整保留。正式資料庫只做唯讀查核；測試不讀寫正式資料。
