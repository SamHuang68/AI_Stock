# 日線分欄品質與來源收據

估值研究版本 `valuation-research-3` 將 OHLC 價格與成交股數分開核對。官方逐欄價格相符、來源身分及交易日通過驗證時，成交量差異不再抹去可確認的收盤價。衝突日的研究成交量仍是 `null`，不能產生量比、帶量突破或通過需要完整 OHLCV 的技術篩選。`0` 股代表明示零成交，和 `null` 不同。

`bars` 保留首次保存數值；官方後續觀測留在 `official_daily_observations`，不同來源回應雜湊保留不同版本。即使後續再次讀到原值，既有官方修訂衝突仍保留在品質門檻內。成交股數採精確比較，不以價格浮點容差吞掉一股差異。這不是自動選擇「最新來源」或宣稱已解決不同成交量口徑。

## 寫入契約

`datastore.upsert_bars` 及 `daily_quality.store_official` 新增可選的 `source_receipt`，舊呼叫與回傳接受筆數保持相容。完整收據目前只支援 `TWSE STOCK_DAY`：

```python
source_receipt = {
    'url': 'https://www.twse.com.tw/exchangeReport/STOCK_DAY?response=json&date=20261001&stockNo=2330',
    'raw_text': raw_bytes.decode('utf-8'),
    'retrieved_at': actual_fetch_finished_at,
    'parser_version': 'twse-stock-day-v1',
}
```

`source_hash` 必須等於完整 `raw_text` 的 UTF-8 SHA-256；不可先重新格式化 JSON 再沿用原雜湊。驗證包括受支援 HTTPS 來源路徑、查詢代號與月份、回應月份與標題身分、原始欄名與說明、重複日期、日期是否晚於取得時間，以及每筆 OHLCV 是否與原回應相符。收據保留原始 `fields`、`notes` 及完整回應；不由既有裸觀測補造原始收據。

`JsonSourceResponse` 保持 `(value, digest)` 兩項解包，新增 `.source_receipt` 屬性。測試 fixture 或舊抓取器回傳普通二項 tuple 時沒有收據，必須明確保留缺漏。

`official_source_receipts` 與 `official_daily_receipt_links` 以新增方式保存，並用資料庫觸發器拒絕修改及刪除。`retrieved_at` 是原始取得時間，`written_at`／`linkedAt` 是實際存入本次資料庫的時間。重播保存收據時不改寫取得時間，也不刷新第一筆收據的寫入時間。只有本次收據直接建立原本不存在的行情列，才記錄 `raw_origin`；價格比對相符不代表知道舊列最初來自何處。

取消檢查、觀測、來源收據、每日連結與品質寫入在同一 SQLite 交易內回滾，不留下只有收據或只有價格的半筆更新。

## 共用讀取契約

`quality_evidence(conn, symbol, market='TW', board=None, start=None, end=None)` 回傳以 ISO 交易日索引的 `priceVerified`、`volumeVerified`、`priceConflict`、`volumeConflict`、`receiptComplete`、身分／收據錯誤及來源收據。讀取時再次檢查來源內容，不把缺少或無效的收據連結當成有效證據。

`quality_summary(conn, symbol, expected, market='TW', board=None)` 以同一組預期交易日提供 observed／accepted／conflicts／missing／invalid 與相應日期。`accepted` 僅在價格與成交量都有完整、無衝突收據時成立；observed 只代表有觀測，不能替代通過品質核對。舊裸觀測列入 receiptMissing，不自動變成完整來源涵蓋。

`receiptComplete` 只判斷來源收據能否通過重新核驗並連回同日觀測；與原始行情的量價衝突分開，因此合法收據可重用、衝突仍另行列出。月份快取須每個預期交易日都有觀測且 `receiptMissing == 0`；`receiptMissing` 包含從未保存有效收據及收據損壞，`receiptInvalid` 另列已存在但內容／雜湊／連結核對失敗者。裸觀測、孤立連結或損壞收據不能讓月份跳過補齊。

估值仍相容既有有效 `bar_quality` 紀錄，但會明示「未保存完整來源收據」。這類紀錄的 `priceVerified` 為 false；只有新的完整來源證據可以讓既有量衝突列的價格通過分欄核對。原始逐列來源未保存時明示未知，不猜測供應商，也不把核對來源寫成原始來源。

本契約改善資料可追溯性與研究可用欄位，不表示 5／20 交易日前瞻成果已成熟，也不表示歷史或前瞻策略有效；相關 `strategyValidated` 與當時可得財報限制維持原義。
