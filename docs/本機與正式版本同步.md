# 本機與正式版本同步

本機 ST 以 `127.0.0.1:18432` 提供服務，程式安裝在 `%LOCALAPPDATA%\StockTerminalLocal\current`。使用者原本的 Git 工作樹、未提交 HTML 與資料原件保留。正式網站繼續使用原私有 gateway 與資料；兩個執行環境不共用 DB。

## 發布來源與資料保護

本機依正式 `current/.private_web_release.json` 的完整 SHA 選擇 `releases/<releaseId>`，只接受測試通過、逐檔程式／公開種子雜湊均一致的 stage。不能挑最新資料夾，也不能把臨時 bootstrap 程式補入舊 stage。正式版必須先包含 `scripts/local_release.py`、`scripts/start_local.ps1`，初次設定才會成功。

同一份 stage 複製至本機安裝目的地後，沿用 `private_web_release.py` 的發布鎖、候選目錄、交易日誌、資料保留與回復機制。正常啟動不執行 Git、不重建 HTML，也不因原工作樹或資料有變動而停在 Git dirty 檢查。

每次需要切換程式前，先拒絕尚有 listener 的 18432，再備份本機 `data` 中全部 SQLite 與其他檔案。SQLite 以備份 API 取得一致快照，核對 integrity、schema、每張表的列數與逐列值摘要，保留 NULL／零差異；WAL 已提交內容納入主備份，WAL／SHM 不當成可獨立還原的資料複製。其他檔案核對 SHA256。備份與收據位於 `backups/資料備份-<實際時間>-<識別碼>`，記錄來源 SHA（無 Git 證據時為 null）、目標 SHA、時間及失敗原因。備份失敗不切換版本。

資料列舉在進入子目錄前拒絕 symlink／junction。整批複製完成後，再核對所有來源 SQLite 的 schema／逐表值、其他檔案 SHA256，以及前後檔案清單，發現背景寫入即保留失敗收據並停止。這是逐檔快照加來源再核對，不宣稱多個資料庫在同一時刻的原子快照；遷移前仍須先完成其他資料寫入工作。

首次遷移從原工作樹複製已驗證的備份至本機 `current/data`；原件不移動、不刪除。其後 `current/data` 是此本機服務持續更新的資料來源，升版由原發布交易保存，原工作樹內的舊副本不會自動回寫。不要同時啟動原工作樹版本，也不要以 junction 讓兩個版本共同寫入資料。

## 初次設定與既有入口

部署者先確認正式新 SHA 的 CI、stage 與實際服務驗收已通過，再按 executable、command line、baseDir、PID 建立時間核對並停止原本機程序。新啟動器不會終止未登記的 legacy 程序。其他可能寫入原資料的本機工作也應先完成。

以明確的受測程式路徑執行初次設定。以下變數由部署者填入實際路徑；`$bootstrapRoot` 必須指向含本文件的受測發布版本：

```powershell
$python = Join-Path $env:LOCALAPPDATA 'Programs\Python\Python312\python.exe' # 改成實際受測直譯器
$originalCheckout = 'D:\Projects\AI_Stock' # 改成實際原工作樹
$sourceRoot = Join-Path $env:LOCALAPPDATA 'StockTerminalPrivateWeb'
$localRoot = Join-Path $env:LOCALAPPDATA 'StockTerminalLocal'
$bootstrapRoot = Join-Path $sourceRoot 'current'
& $python -B (Join-Path $bootstrapRoot 'scripts\local_release.py') --install-root $localRoot setup --original-checkout $originalCheckout --source-install-root $sourceRoot --python $python
if ($LASTEXITCODE -ne 0) { throw '本機安裝未完成，請查閱錯誤及備份收據。' }
& (Join-Path $localRoot 'start_local.ps1') -InstallRoot $localRoot
```

`local_install.json` 保存原工作樹、正式安裝根目錄、Python 絕對路徑與首次遷移收據。安裝根另有 `start_local.ps1`、`local_release.py` 穩定入口；更新時從已驗證的 `current/scripts` 更新入口，Python 穩定入口從目前版本載入並驗證發布 helper。

部署者只在核對原啟動檔沒有使用者修改、已保留原檔與雜湊後，將本版 `START_TIP.cmd` 與 `scripts/go.ps1` 的入口修正套到已登記工作樹。不能批次覆蓋整個工作樹。原快捷方式繼續指向 `START_TIP.cmd` 即可。該批次檔只轉交 PowerShell，不再依埠執行 taskkill。

`go.ps1` 僅在設定內 `originalCheckout` 與目前工作樹完全相符、且是一般啟動時轉接；隔離 worktree 不受影響。明確的 `-Worktree`、`-Pull`、`-UpdateOnly`、`-RebuildOnly` 保留開發流程，不能把這些開發動作當成已部署版本同步。

## 啟動、失敗與核對

每次正常啟動比對正式 SHA，必要時先備份再升版。啟動器使用釘選 Python 的 `-B -u`、隱藏視窗及安裝根的 `logs`；唯一綁定位址是 `127.0.0.1:18432`。登記程序的 receipt 包含 PID、建立時間、完整命令列、執行檔及 baseDir。只有身分完整吻合的舊本機程序才可因升版停止；任何無關 listener 或 PID 重用都明確拒絕，不掃除其他 Python。

開啟瀏覽器前，同時核對 health 的 SHA、baseDir、Python、綁定位址、埠，以及 Windows listener 的擁有 PID。檢查失敗會留下日誌而不宣稱更新成功。正式 stage 缺失、略過測試、SHA 不符或被修改，在停止既有本機程序之前即拒絕。本機已管理程式若被修改，也保留修改並拒絕升版。

程式切換沿用 `private_web_release.py` 的交易日誌與回復；回復操作前同樣需要停止已辨識的本機程序並備份資料。若 stable 入口更新中斷，可使用 `current/scripts/local_release.py --install-root <本機根> sync` 修復入口；同 SHA 不切換資料。不要手動把程式或 DB 蓋回 `current`。

初次設定另有 `local_setup_pending.json` 收據，在建立 `current` 之前寫入原路徑參數、目標 SHA 與備份位置。若程式已切換、設定或入口寫入失敗，使用與第一次完全相同的 `setup` 指令重跑即可：只補齊入口與設定，不重複發布或複製原資料。若在程式切換前中斷，重跑會保留已複製資料、重新備份後續接發布。不同原工作樹／來源路徑參數會被拒絕；收據未完成時一般啟動會明確阻擋。不要刪除 `current`、備份或 pending 收據來繞過檢查。

私有 stage 不包含 WaveDeck 執行套件；本功能不移除或替換原本獨立的 WaveDeck 安裝與入口，也不宣稱它已隨 ST 同步。

此部署一致性驗證只能證明程式、資料保留與入口行為，不能代替策略有效性或真實前瞻成熟驗證。
