## 結論與責任邊界

**已證實的技術根因是昨收來源與校正條件錯誤。** 主圖採 Yahoo 昨收 49302.00，下方小框採 TWSE MIS 官方昨收 48341.31；既有校正只處理「最新 K 棒仍落後一天」，錯把「K 棒已是今天」當成「昨收也正確」。同日現價 48625.83 因而在主圖顯示 −676.17（−1.37%），在小框顯示 +285（+0.59%）。正確未取整漲點為 +284.52。

**目前證據不支持「PR #198／#199 把已存在的正確昨收修正覆蓋掉」。** 同一事故快照在 PR #198 前的來源與 PR #199 來源都重現錯誤，兩版 `patchTwIndexHeader` 區塊 SHA-256 完全相同。Claude 的 PR #197 修正建立於 PR #199 之後。沒有原先正常畫面的完整來源、時間與網路封包，不能把使用者曾看到正確數字等同於已證明來源契約正確，也不能虛構一個由 Codex 引入的新變更。

## D4：發生根因、流出根因與因果證據

### 發生根因

1. 主圖把 Yahoo 有值的昨收當作可用基準；不同欄位的資料日期與可信度沒有一起核對。
2. 官方校正具有不成立的假設：最新 K 棒已更新，就不必再校正昨收。故「現價新、基準錯」不能被校正。
3. 單檔與批次報價尚未把 `^TWII` 納入官方 override，其他消費路徑仍可能得到錯誤基準。

### 流出根因與 Codex 改善責任

- PR #199 版尚無兩份後來新增的專用測試；既有報價測試沒有覆蓋「同日、同現價、不同昨收」。合理值檢查不會拒絕 −1.37%。
- Codex 先前實際部署驗收記錄了版本、靜態資產、修改的路由與業務契約，但沒有跨主圖／小框／報價端點的數值斷言。這是可查的驗收覆蓋缺口，不能推論歷史上完全沒有人手查看畫面。
- 事後前端 fixture 原採畫面反推的 48340.83，後端採後來確認的 48341.31；兩者顯示同樣 0.59%，且取整均為 +285。分開維護會讓跨表面差異難以被看見。本次統一為同一份已核對的數值，明示其不是原始封包。
