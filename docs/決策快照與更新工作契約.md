# 決策快照與更新工作契約

## 唯讀與更新

`GET /pulse`（包含舊 `?refresh=1`）、`GET /decision/context`、`GET /pulse/update-status`、`GET /updates`、`GET /updates/archive` 只讀已保存結果。空資料庫讀取不建表、不啟動工作、不下載來源、不推進預警。

Owner 可用 `POST /pulse/refresh`（空物件）或 `POST /updates`（`type`、`params`）接受持久工作，回傳 HTTP 202；Reader 不能提交或重試。`POST /updates/retry` 只接受原 `jobId`，參數與沿革由伺服器保存值恢復。GET 查詢不具有更新權限。

正式服務啟動唯一 Pulse worker，接受 boot、定期（預設 60 秒）與 Owner 要求。它重用既有來源、計算與私人 gateway，沒有新增 HTTP 對外服務或來源存取權。期權與原有日夜盤研究來源完成後，只交回同一 Pulse writer 發布市場快照。`shadowOvernightIntraday` 關閉時不接受研究更新或重試。

## 成功與恢復

發布先持久保存完整輸入及意圖，再以發布收據防止重複預警，最後在同一 SQLite 交易提交決策快照、歷史、修訂水位及既有通知邊界的收據。提交成功後才更新記憶體。磁碟失敗保留上一個成功快照；重啟先恢復未完成意圖，規則版本不符時停止新發布並保留意圖供查核。

通知沿用原有 feature flags、既有訂閱與傳送邊界；本輪不啟用通知。停用狀態不建立等待補送事件。已開始嘗試的傳送不自動重送，部分失敗保留原結果。

Pulse 工作只有核對到已提交 `snapshotId`／`revision` 才能成功；成功提交後的工作收據寫入失敗只重試收據，不重跑來源。重啟會核對已提交歷史，將未提交的執行中工作標示中斷。Pulse 保留最近 100 個終態工作，決策保留最近 500 個快照；其他持久更新工作沿革不自動刪除，可透過 archive 匯出。

瀏覽器取消或等待逾時只停止接收，不表示伺服器來源已停止。工作超時、停止檢查會阻止開始新提交；不合作的來源真正返回前不釋放工作槽。已持久化的發布意圖仍依恢復協定完成。

## 身分、效期與個人檢視

正式快照提供 `snapshotId`、`revision`、`inputHash`、`rulesDigest`、`persistence=committed`。完整輸入與規則版本參與識別，晚到舊工作不可覆蓋新快照。

POST 的個人投組檢視只有 `parentSnapshotId`／`parentRevision`，不假冒新的正式修訂，也不改寫市場歷史。前端跨模式比較共同市場修訂水位；較新 Pulse 到達時先清除舊完整 Context，避免摘要與不同市場世代的個人檢視混用。相同修訂的 Pulse 不清除目前個人檢視。

來源時間與建立時間分開；缺少、未來或過期來源不能由新的 `updatedAt` 救回。效期使用已存交易日曆；沒有時明示工作日備援。週末有效收盤可以沿用，未完成的前交易日盤中報價不能冒充收盤。GET 只投影目前效期並保留原始證據，不重新發布。

實際投組採有效現價乘股數；空持倉不改用自選清單。觀察池等權與手動情境需明確選擇，手動原文不外送。缺價格、未知幣別、歷史或 Beta 涵蓋不足保留完整分母、回傳未知風險，不重新加權已知部分。沒有完整持倉輸入時不提供個人部位上限。目前個人投組計算限臺股／新臺幣，未加入跨幣別換匯模型。

## 前端接線與範圍

載入次序：`投組資料契約_v5.js` → `decision_data_v5.js` → `更新工作_v5.js`。`decision_v5.js` 另依賴 `ai_runtime_client.js`；`更新工作中心.js` 依賴 `shell_v5.js` 與 `更新工作_v5.js`。更新中心重複開關與頁面隱藏會釋放訂閱／輪詢，寫入期間有提交鎖。

AI 結果必須收到串流完成收據並有正文才算完成；截斷、錯誤、取消或過期 Context 保留錯誤狀態。AI 不改寫 deterministic DecisionContext。本輪只復用既有日夜盤／期權計算與市場快照；沒有新增研究模型、AI 任務核心或宣稱支援未實作的研究快照差異介面。
