## D4｜發生根因與未被測試攔下的原因

### 發生根因

1. `business_day_age()` 只排除週末。9/24 → 9/29 被計為 9/25、9/28、9/29 共 3 天，超過 2 天門檻；共用交易日曆實際只列 9/29 為表定交易日，應計 1 天。ETF 管線沒有使用專案已存在的休市參考。
2. 持股解析把「股票連結、一般股票代號、非負整數數量」當成全部 ETF 部位的形狀。期貨與債券不符合這個假設，即使網頁有資料也會被當成無資料。
3. 消費端以空清單代替某一期缺漏，導致缺資料有機會被判成整檔新增或出清；這與快照允許部分來源成功的驗收契約不相容。

### 流出原因

- 日期測試只覆蓋週末，沒有連假、臨時休市與未知年度。
- 多數 tracker 測試替換整個 `fetch_one()`，無法發現真實 HTML 的不同資產格式。
- 舊 API 只留末 4,000 字，畫面又只呈現最後三行。最後完成的單檔失敗容易被誤認為整批拒絕原因；候選日期分布與完整終止結果未持久保存。
- 舊測試沒有涵蓋「前次成功 → 本次逾時 → 服務重啟」、部分可比較／部分缺漏，以及非股票部位進入下一期共識報表的路徑。

## D5｜永久修正

| 修正 | 約束與目的 |
| --- | --- |
| ETF 驗收與健康狀態共用臺股交易參考 | 排除已核對休市日；未知年度保守計平日並明確揭露，不冒稱官方日曆完整 |
| 支援名稱型部位、特殊期貨代號、負數口數及未揭露數量 | 數量未知保留為 `null`；名稱識別碼不冒充股票代號 |

| 異動比較增加資料條件 | 缺一期、來源不同、前十大範圍、格式切換、同揭露日等不判定買賣 |
| 非股票部位獨立顯示 | 保留明細，不納入個股共識分數，不呼叫股票均量、股票原因分析或股票 K 線 |
| 同日部分成功只重試缺漏 | 不讓一次部分成功造成當日永久跳過，也避免重抓已取得的整個觀測池 |
| 每次更新保存作業編號、逐筆紀錄、驗收及終止結果 | 正常、拒絕、逾時、啟動失敗與未完成作業都有可追查紀錄；重啟不以舊成功覆蓋新失敗 |
| 明確拒絕不支援的歷史回補 | MoneyDJ 最新資料不能被寫成多日歷史；既有歷史檔完整保留 |

診斷與正式快照共用根目錄，紀錄位於 `etf_history/_runs/`。每次作業的 JSONL 含來源回應、解析結果、各檔來源日、候選驗收與終止事件；JSON 保存結果；API 另外保存完整標準輸出。畫面可展開更新證據與完整紀錄。

## D7｜防再發控制

- 上述測試納入既有 Windows／Ubuntu CI，固定以休市與不同資產形狀驗證，不能靠牆鐘或付費服務才通過。
- 每次更新的成功數與新鮮數分開顯示；「有更新」不等於「全池完整」或「所有資料都是今天」。
- 來源缺漏、真正過期、日曆年度未知與不能比較會保持可見，不改成零持股、零數量或無異動。
- 維護日曆時仍沿用同一份 `台股交易參考.json`，避免 ETF 與個股再次分叉。新增年度與臨時休市須有官方證據。
- 既有每日 ETF 排程會使用同一套驗收、診斷與缺漏補抓規則；本輪沒有新增券商或模型 API。
