## 本次修正

- 每日留存即使目前輸入少於新增訊號需要的歷史根數，仍核對既有事件是否成熟；短歷史不能新增訊號。既有首次價格、事件與成熟結果不可覆寫。
- 5／20 日結果從事件後第一個實際交易日收盤進場，分別需要事件後 6／21 個完整基準日及個股價格。統一回報 `awaiting_observed_sessions`、`missing_stock_sessions`、`missing_benchmark_sessions`、`not_evaluated_current_input`，不壓縮缺日。
- 新增訊號的排除原因區分當日缺價、歷史不足、歷史缺日／不完整；保留舊 `missingPriceSymbols` 欄位。詳細原因來自本次實際核對，舊收據沒有的欄位不倒填。
- 成熟計算只接受既有 `complete_bar` 契約的完整 OHLCV；缺值或非法價格列明 `invalidPriceDates`，舊有不完整證據保留但不得產生報酬。
- 狀態讀取使用單一 SQLite 唯讀交易；介面顯示每一期成熟及待核對數。零成熟、零交易與零報酬是不同狀態。
- Chromium 離線觸控驗收使用實際更新中心及體檢元件，固定 Playwright 版本；行動直式、橫式與 CPU 降速模式納入 Windows／Linux CI。固定收據明示為介面測試，非市場績效。

執行：`python -m unittest tests.test_forward_observation_contract -v`、`node tests/stock_health_v5_selftest.js`；瀏覽器首次使用需 `npm ci --ignore-scripts`、`npx playwright install chromium`，之後 `npm run test:browser`。完整檢查以 `.github/workflows/ci.yml` 為準。浏览器輸出在 `scratch/reliability-browser/`，不提交測試資料。
