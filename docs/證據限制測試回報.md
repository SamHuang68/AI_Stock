# 三項證據限制測試回報

Stock Terminal 在「圖表 → 體檢 → 研究維護與每日事件留存」顯示最新驗證、每日完整報告與變化紀錄。這是本機證據檢查，不代表研究已找到投資優勢，也不是每日重新執行整套程式單元測試。

## 檢查內容

| 限制 | 檢查與回報 | 不可省略的邊界 |
| --- | --- | --- |
| 研究優勢 | 主情境與固定 RSI 的結果、研究協定、研究與行情截止日、最近來源更新時間 | `no_candidate` 保持無候選；歷史通過仍僅供前瞻觀察，不自動升級 |
| 前瞻結果 | 真實事件數、5／20 日成熟數、未到期及觀察期已到仍未結算數、每日留存缺口 | 次日收盤進場，須有事件後 6／21 個真實交易日；缺失行情可能延後到期判讀，不補造歷史事件 |
| 資料覆蓋 | 完整／部分還原檔數、當期未對齊代號、已知交易日缺日、來源修訂衝突、待完成來源 | 交易日曆與證券生命週期仍是有限參考；局部覆蓋不能宣稱完整歷史主檔 |

「檢查完成」表示檢查程序已執行。各項仍可能是等待證據、涵蓋有限、尚未驗證優勢；程序例外或協定不符會標示「檢查失敗」。程式失敗、資料不足及投資結果不佳分別呈現。

## 執行時機

- 沿用已啟用的每日留存背景執行緒及共用工作佇列，不增加另一套排程服務。
- 既有來源更新於交易日 18:30 執行；19:30／20:30 僅重試未完成來源。每次實際來源工作後重新計算本機研究並留下報告；來源或留存拋出例外也留下失敗報告。
- 每日 20:40 起，下一次背景檢查會排入本機結報。背景間隔為 10 分鐘，工作繁忙時依序排隊；休市仍結報，不因此呼叫外部來源。
- 結報區分預定日期與實際檢查日期。跨午夜執行不會阻擋翌日晚間正常結報。
- 可按「重算並檢查三項證據（僅本機）」即時重算及驗證。它不更新外部行情、不呼叫模型、不傳送通知、不修改研究門檻或候選。

需主機與 ST 服務運行，且每日留存已啟用。主機離線時無法產生報告；當日 20:40 後恢復服務可再排結報，跨日不補造離線日快照。畫面顯示實際最近檢查時間，不能把安裝完成當成未來排程已執行。

## 保存與查閱

報告存於正式站資料目錄的 `stock_evidence_reports.sqlite3`。行情、前瞻帳本及研究協定均由既有管線管理，回報模組以唯讀方式取證。

同日相鄰的完整證據相同時沿用報告 ID，另更新最近檢查時間；證據清單、失敗狀態、日期或研究來源改變就追加快照。A → B → A 會保留三次變化，不覆寫舊報告。

每頁 20 份，按「載入更早報告」可持續查閱。每份歷史報告包含量化差異與完整當時快照，舊失敗原因不因後來成功而消失。全部資料保留，不自動裁切歷史。變化是資料與研究狀態的差異，不等於績效改善。

API 沿用擁有者權限：`GET /stock-signals/research/status?reportBefore=<ID>` 與 `POST /stock-signals/research/refresh`，後者須為單一欄位 `{"checkEvidence":true}`。讀者及未登入者無權讀取維護報告或啟動檢查。

## 驗證

`tests/test_證據限制回報.py` 覆蓋判定邊界、唯讀前瞻計數、失敗持久保存、來源例外、歷史詳情、完整缺口去重、分頁、休市、重啟及跨午夜排程。前端契約測試覆蓋文字跳脫、未到期／待結算、舊失敗可回查及空報告。整體回歸與 CI 於程式變更時執行；正式每日報告只做上述證據檢查。
