# 類股熱力圖：手機橫式可視區修正

## 問題與根因

原先寬度低於 980px 就把四張摘要卡排成兩列，並把熱力圖與焦點掃描上下分割。父層仍限制在一個螢幕高度，內層採 `min-height:0`，因此「沒有水平溢出」並不代表主要內容可讀。

修正前在 Chrome 的 844×390 CSS 像素視窗重現：熱力圖容器只有 40px，做多與做空清單都是 0px。失敗證據保留於 `logs/類股可視區驗證/修正前`。

## 修正範圍

- 僅調整類股熱力頁，適用橫式且可視高度不超過 540px。
- 四張摘要卡改為單排。
- 熱力圖與焦點掃描恢復左右並排，主區保留 380px 高度。
- 空間不足由頁面垂直捲動承接；熱力圖及兩張焦點清單保留各自的原生觸控捲動。
- 名稱允許換行，熱力格名稱 11px、漲跌幅 16px；焦點名稱與代號 10px、漲跌幅 11px。
- 保留底部安全空間及「上下滑動看全部」提示。
- 不改市場資料、排序、股票跳轉、台美股漲跌色或直式版型。

## 驗收標準

1. 熱力圖可容納至少三個完整列，並在主區捲至可讀位置後，與實際螢幕交集仍有至少三列。
2. 做多、做空清單分別移入可視範圍後，至少三列完整可讀。
3. 使用實際 `touchStart`、連續 `touchMove`、`touchEnd` 驗證外層、熱力圖及焦點清單可捲動。
4. 手勢停止後等待，捲動位置不自行回彈。
5. 同一份 DOM 在 390×844 → 844×390 → 390×844 往返，最後一列可達且位置穩定；不能靠重新載入路由掩蓋問題。
6. 390×844 直式與 1440×900 桌面不退化。

測試將固定的 49 個類股、兩組各 20 筆焦點資料送入原始前端渲染流程，僅作版型與互動驗證。固定資料不是金融觀測結果。實際來源截圖必須冷載入頁面清掉測試快取，且確認測試名稱不存在。

## 執行方式

```powershell
$env:ST_HEAT_ONLY = '1'
$env:ST_EVIDENCE_DIR = 'logs/類股可視區驗證/驗收'
node tests/mobile_portrait_browser_gate.mjs
```

移除 `ST_HEAT_ONLY` 可連同既有十六個功能頁、圖表翻頁與深連結執行完整回歸。瀏覽器可由 `CHROME_PATH` 指定。此驗證使用隔離的 Chrome 設定，不使用個人 Chrome 設定或登入資料。

## 驗證邊界

Windows Chrome 手機視窗模擬與觸控事件不是 iPhone 實機驗收；iPhone Chrome 的瀏覽器工具列收合與實機手感仍需發布後確認。本輪僅修正與驗證工作區，不代表已提交、推送或部署。

## 證據與複審紀錄

- `修正前`：重現 40px 熱力圖與 0px 清單，失敗保留。
- `第一輪`：容器尺寸改善，但缺乏螢幕交集與觸控驗證，被另一位同供應商、未生產本輪程式的審查員退回。
- `第二輪`：Chrome 合成捲動未產生有效手勢，未宣稱觸控通過；後續改為實際觸控事件序列。
- `最終驗收`：固定資料可視區、觸控及旋轉測試通過；其中名為「實際來源」的舊圖片仍混有焦點測試快取，不能作為全頁真實資料證據。
- `完整回歸`：90 筆檢查零失敗；其舊版實際來源圖片具有上述相同限制。功能頁、翻頁與深連結回歸結果仍有效。
- `確認版`：加入冷載入及測試名稱排除，作為本次真實來源截圖的正式證據位置。舊失敗與被退回證據不刪除、不改寫成通過。

確認版結果：六種尺寸、三次同頁旋轉及一張真實來源觀察，共十筆紀錄，零失敗。四種短橫式的熱力圖容器高度為 302–316px，主區移至可讀位置後螢幕內均有三個完整列；兩個焦點清單各 124px，分別移入畫面後各有四筆完整可讀。真實來源截圖顯示 49 個類股與實際焦點公司，沒有測試名稱；該次來源日期為缺值，照原資料顯示「—」，不自行補造日期。

靜態版型、殼層、視覺系統與手機翻頁四組 JavaScript 測試皆通過；可重現建置的兩個 Python 測試通過。主要修改檔為 `src/ui/heat_v5.js`，新增量測位於 `tests/heat_viewport_checks.mjs`，由既有瀏覽器驗證入口執行。
