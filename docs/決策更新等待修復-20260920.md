# 決策更新等待修復

使用者回報策略決策中心的更新按鈕停在「等待市場快照」。實際頁面同時顯示「已讀取最新提交的市場快照」，既有關聯追蹤顯示背景讀取及個人化決策請求在 708 毫秒內成功；兩端後端的工作與已提交快照亦一致。

## 原因與行為

背景刷新呼叫正式 `render`，經過 `ensureMount` 時把任何進行中請求都當成人工更新，因此將按鈕停用。背景請求完成時，舊 `finally` 只替前景請求復原按鈕，造成資料已更新但按鈕持續鎖住。既有生命週期測試替換了 `ensureMount` 和 `render`，未涵蓋這個交互作用。

修正後，背景讀取不會把人工更新按鈕設為忙碌；收尾只有目前請求可以清除狀態並復原按鈕。背景讀取期間的人工更新仍沿既有流程等待後送出，重複點擊共用同一個前景工作。離頁或被取代的舊請求不能解除新請求的忙碌狀態。

原有市場工作等候上限未包含後續個人化決策讀取，這次將人工更新整段流程限制為 90 秒、背景及 Reader 純讀限制為 12 秒；逾時保留既有已提交決策並顯示可重試訊息。瀏覽器停止等待不會取消伺服器工作，逾時後晚到回應不可覆寫畫面。

決策頁另明確要求資料層傳回讀取失敗：HTTP 失敗、空白、無效 JSON 或缺少必要內容皆顯示未完成，不再把舊快照當作本次個人化成功。其他資料層呼叫者保留既有快取備援行為。

## 驗證邊界

新增 `決策更新狀態_selftest.js` 以完整正式模組驗證背景與人工更新，保留實際 `ensureMount`、`render` 及事件監聽；假網路與時鐘只控制回應順序、失敗及逾時。回歸列入分享包及精確提交發布包必要檔案。

正式發布後須用實際瀏覽器確認：進入決策頁後背景刷新不鎖按鈕；點擊更新能取得工作與新快照並復原；等待下一次每分鐘背景刷新後仍可再次更新。本輪發布 SHA、CI、兩端實際操作及資料保留證據另存工作樹的交付紀錄。
