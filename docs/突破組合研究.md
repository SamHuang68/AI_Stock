# VIDYA 現金受限投組工程研究

`server/突破組合研究.py` 提供確定性純計算與唯讀快取介接。此版是 2330／0050 小範圍工程案例，不代表文章策略重現、全市場回測或投資有效性驗證。缺少 ETF 公司行動涵蓋等證據時，結果會保留未知，不能把測試通過寫成真實策略績效。

## 公開介面

```python
build_saved_portfolio(db_path, as_of=None, *, now=None, config=None)
build_portfolio(datasets, market_dates, *, sample_start=0, as_of=None, config=None)
simulate_portfolio(datasets, market_dates, observations, *, sample_start=0,
                   config=None, side_cost=0.0025, benchmark_symbol=None)
vidya_value(closes, *, length=20, cmo_length=9)
daily_excess_sharpe(curve, benchmark_curve)
```

`build_saved_portfolio` 僅透過 `mode=ro`、`PRAGMA query_only=ON` 與同一 SQLite 讀取交易取得快照，沿用 `突破觀察.load_dataset` 與 `K線事件.freshness`。市場時間軸採 loader 的 `session_dates`，以年度休市／開市資料與已核對月份重建；兩檔同日未匯入時仍保留該市場日，不從已有行情日期反推。缺少完整市場日介面時不回退猜測。不建立表格、不修改行情、不下載、不啟動更新。快取入口固定 2330／0050，取近五年與必要暖機；新建快取或查無來源時回 `unavailable`。API 路由與前端由研究工作流整合。

`build_portfolio` 接受一至二十個明確標的、最多六千個排序且不重複的市場交易日。每個 dataset 包含：

| 欄位 | 契約 |
| --- | --- |
| `rows` | `date/open/high/low/close/volume/source/priceBasis/issues`；來源日期不同時必須以 `sourceDate` 揭露 |
| `calendar_years` | 已核對日曆年度；共同缺日仍須出現在 `market_dates` |
| `action_days` | 已知公司行動日期；不從價差推論分割股數 |
| `action_coverage` | `(start_date, end_date, source)`，來源須為 TWSE／TPEX |
| `action_coverage_kind` | ETF 必須明示 `etf`；股票除權息表涵蓋不等於 ETF 涵蓋 |

`simulate_portfolio` 是可獨立驗證的記帳核心，明確接收逐收盤的 `date/vidya/entrySignal/reason`，不接受不明日期或非布林訊號。正式研究入口由 `build_portfolio` 自行計算這些觀察，不從前端讀入交易提示。呼叫端提供的市場日曆必須完整，核心不自行猜測被省略的共同休市／缺資料日。

## 計算與時序

預設 VIDYA 每日取最後 60 根市場日資料，以前 20 根收盤 SMA 初始化，其後對每根計算最近 9 個收盤變化：

`CMO = (上漲幅度總和 − 下跌幅度總和) / (上漲幅度總和 + 下跌幅度總和)`；分母零時 CMO 為零。

`alpha = 2 / 21 × abs(CMO)`，`VIDYA = 前值 + alpha × (收盤 − 前值)`。這是明示的固定窗口工程公式，不等同無限歷史遞迴。

前一收盤不高於前一 VIDYA、當日收盤高於當日 VIDYA，才產生一次穿越訊號。訊號於收盤完成，最早下一市場日開盤買進。收盤低於 VIDYA，或收盤不高於原始進場價的 92%，才安排下一開盤賣出。日內高低價不決定停損先後，也不先以當日收盤或成交量排序開盤資金。

同日先賣出，再依代碼遞增買進。每筆預算為可用現金與配置基準乘配置比例的較小值；配置基準可為初始本金或前一日已知收盤權益。股數向下取整至交易單位，不借貸、不加碼。買入扣 `股數×原價×(1+每邊成本)`，賣出收 `股數×原價×(1−每邊成本)`。原始成交價格不調整，成本另外揭露。

三種固定情境與 `突破成交研究` 一致：`gross=0`、`baseNet=0.0025`、`stressNet=0.005`。每邊成本已合計費用與滑價，不再重複扣除；未模擬最低手續費、逐市場稅制、量價容量、委託簿或漲跌停可成交性。

進場下一市場日資料不足時，取消該次委託並記錄未知，不跳到後一日冒充次日成交。一價棒、零量或不完整 OHLC 只能表示缺少開盤可成交證據，不能推定撮合成功。這是日線研究的事後證據檢查，不用於預先挑選當日贏家或改寫前一收盤訊號。退出遇缺資料或一價棒則保留待出場，到下一個可核對開盤處理，仍保留執行未知狀態。期末未平倉保留部位與原因，不強制賣出，亦不扣尚未發生的出場成本。

## 品質、績效與空值

官方來源、原始價格基準、來源日期、日曆年度、公司行動涵蓋、已知停牌／終止交易期間均為必要檢查。缺日不補價格，無效 OHLCV 不產生收盤訊號。公司行動穿越指標窗口時，原價比較保留未知；跨持有期時未建立股數及現金權利，後續權益持續未知。此版本沒有把官方參考價比值視為分割或含息報酬。

每日權益為現金加當日原始收盤價乘持有股數；MDD 比較初始本金與所有已知每日高點。持有日缺價則當日 `equity=null`，隔日報酬不跨越缺口計算。總績效受未知決策或估值影響時，`totalReturnPct/maxDrawdownPct=null`，仍保留逐日曲線與 `observedDrawdownPct` 供核對。

0050 基準使用相同起始收盤後的下一開盤、相同成本與原價市值，不強制期末出場。`dailyExcessSharpe` 用同日「投組日報酬 − 0050 日報酬」的平均除以樣本標準差，再乘 `sqrt(252)`，數學上是資訊比率，並非以無風險利率計算的 Sharpe。基準缺日、估值未知、樣本不足或變異為零時皆回 `null` 並附原因，不用成交筆數代替每日樣本。

沒有交易且訊號完整可核對，報酬可以是零，但勝率為空值。已平倉且淨損益恰為零，以 `netZeroTrades` 記錄；資料不足則是 `unknown`，不能與前述零值混淆。`tradeStatus` 分別為 `no_trades/open_only/closed`，`pending/rejected/decisionIssues/valuationReasons` 留下具體原因。

## 固定時序評估與有界參數

預設切分日固定 `2024-01-01`，不隨追加測試資料重新切出比例。切分日前後分別用相同初始本金，測試暖機只用已發生價格，不承接訓練部位。`evaluation` 明示 `optimized=false`；沒有使用訓練資料選參，也沒有從測試集挑選最佳參數。切分日前後不足時回 `insufficient`。這是可重現的固定參數評估，不能宣稱經過模型選擇後的樣本外有效性。快取與品質證據可能事後補齊，並非每個歷史時點當下已取得的資料快照。

| 參數 | 預設 | 允許範圍 |
| --- | --- | --- |
| `initialCapital` | 1,000,000 | 大於零且不超過一兆 |
| `maxPositions` | 2 | 1–20 |
| `allocationFraction` | 0.5 | 大於零且不超過 1 |
| `lotSize` | 1 股 | 1–1000 |
| `stopLossPct` | 8 | 大於零且小於 100 |
| `vidyaLength/cmoLength` | 20／9 | VIDYA 2–120、CMO 1–120 且不長於 VIDYA |
| `warmupBars` | 60 | 3–504，且多於 VIDYA 長度 |
| `capitalBasis` | `initial` | `initial/previous_close_equity` |
| `testStart` | `2024-01-01` | 固定 ISO 日期；`null` 不產生切分評估 |

## 獨立手算測試

`tests/test_突破組合研究.py` 驗證雙邊成本、現金競爭、最小交易單位、先賣後買、前日權益配置、VIDYA 初始化及穿越、下一開盤成交、收盤停損、每日市值回撤、公司行動未知、ETF／來源日期／停牌排除、零值狀態、固定切分、不看未來資料與 SQLite 唯讀。

具體案例：本金 1000，開盤 100，每邊成本 1%，買 9 股花 909，現金剩 91。持有收盤 110、90 時，權益分別是 1081、901，因此 MDD 為 `180/1081×100%`。收盤 90 觸發停損，下一開盤 105 賣出取得 935.55，期末資金 1026.55，淨利 26.55。另一組本金 5000、40% 配置、每三股一單位、每邊 25 基點，在 47 買入 42 股、45 賣出後，現金為 4906.34、淨損 93.66。測試直接斷言這些數字，未用受測函式產生期望值。

唯讀 adapter 的單元測試用真正 SQLite 驗證寫入被拒及檔案內容不變；`tests/test_投組研究整合.py` 再以真實 `突破觀察.load_dataset`、來源品質表、年度日曆與公司行動涵蓋完成整合，沒有替換 loader。涵蓋共同缺日、尾端缺日、來源日期與價格基準不符、ETF 限制、非官方日曆來源，以及截至日之後價格和公司行動不改變歷史結果。fixture 通過不證明真實 0050 涵蓋完整，也不取代行情端的正式資料核對。
